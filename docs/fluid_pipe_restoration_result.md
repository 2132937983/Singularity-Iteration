# 青铜 / 钢流体管道实施记录

2026-09-29。采用已确认的 A 方案：两个新方块的 `size` 状态控制四种尺寸，方块及物品通过 tint 染色。

## 内容与兼容

- 新方块：`mio_icif:pipe/fluid_pipe_bronze`、`mio_icif:pipe/fluid_pipe_steel`。
- 八种物品：`mio_icif:pipe/fluid_pipe_{bronze,steel}_{tiny,small,medium,large}`。均堆叠 64，名称为微型/小型/中型/大型青铜管道或钢管道。
- 新方块实体 ID：`mio_icif:fluid_pipe`。材质来自方块，尺寸保存在方块状态，流体与连接端口随实体保存。
- 旧 `pipe/block_pipe_water`、`pipe_water` 实体 ID、1000 mB 容量、200 mB/t 自动输出、旧配方及贴图保留。仅从创造栏隐藏旧输水管道，不转换存档中的管道。抽水管道和物品管道保留原状。
- 材质/尺寸定义放在 `core/api/transport`，供附属引用；方块、物品、注册与染色实现在 `common`。

## 参数

下表为容量 mB / 向非管道邻居自动输出总限额 mB/t：

| 材质 | 微型 | 小型 | 中型 | 大型 |
|---|---|---|---|---|
| 青铜 | 400 / 20 | 800 / 40 | 2400 / 120 | 4800 / 240 |
| 钢 | 800 / 40 | 1600 / 80 | 4800 / 240 | 9600 / 480 |

直径分别为 4、6、8、10 像素。青铜 RGB 为 174/81/17，钢为 128/128/128；硬度 1.0，抗性 5.0。钢配方使用已有 `adviron` 外壳和板。

六个外壳横放上下两行合成 6 根微型管，竖放两列合成 3 根小型管；改用板对应 2 根中型或 1 根大型。配方、解锁、模型、语言和掉落均已注册。

## 使用和行为

1. 手持相应尺寸物品，点击机器或管道放置；开启点击方向，并开启相邻管道对应端口。其余面用普通扳手或电动扳手切换。
2. 潜行使用扳手拆除，掉落保持材质和尺寸；中键选取也保持尺寸。管道物品不保存内部流体。
3. 管道本身不抽液。机器需要主动输出（如流体弹出升级），或使用已有抽水管道作为来源。
4. 管道之间采用 IC2 的流体量均分；不会把“向机器输出”的限额再套在管道间。机器方向共享一份每 tick 总限额，多个出口不会让总速率翻倍。
5. 原版流体能力的 `fill/drain` 按当前容量处理；外部泵主动抽取不属于管道的自动输出限额。
6. 管内不混合不同流体/不同组件。关闭端口后，之前缓存的能力引用也拒绝读写转移；未指定面不暴露新管道的流体能力。
7. 拆除时，内部流体严格大于 1000 mB 才尝试释放一个世界流体源。释放安排在拆除完成后，要求位置仍为空气且区块已加载；不可放置的流体不生成源。其余流体丢弃，与物品掉落分开处理。

保留现有转移缓冲、失败重试和每 tick 预算保护，避免第三方流体处理器异常时重复扣液或复制流体。新旧管道可以互接，但旧管道继续采用旧规格。

## 资源与验证

28 个分段方块模型由两种材质共用；8 个物品模型显示对应粗细。五张灰度 PNG 从仓库的 `source/IC2Code 1.12.2/assets/ic2/textures/blocks/transport/` 原样复制，使用侧面及四尺寸端面纹理，没有改动旧管道资源。

资源生成：`python tools/fluid-pipes/generate.py`。
资源检查：`python tools/fluid-pipes/verify_assets.py`，遍历两材质 × 四尺寸 × 64 种连接组合，并核对配方材料、模型纹理引用、掉落和语言键。

`FluidPipeGameTests` 使用注册 ID、core 接口和真实服务端方块 ticker 验证：

- 八种物品真实放置、端口初始化、模拟/实际填充、容量、混液拒绝、保存重载、掉落和中键选取。
- 八种规格连接两个储罐，连续测量实际总输出和补液量，验证额定速率与流体守恒。
- 大小不同的管道均分，扳手切断两端，旧管道 ID 和流体重载兼容。
- 被动管道不从相邻满罐抽取；1000、1001、2400 mB 拆除释放阈值。

已有电网测试在一次完整回归中触发批量建场景的拓扑事件队列上限；将四项电网链路测试分批执行，未修改生产电网逻辑或降低断言。

最终验证：`gradlew build runAddonGameTestServer --offline --console=plain -q` 退出码 0，全部 30 项 GameTest 通过；构建包含 core 架构与分发边界检查。资源检查覆盖 512 种组合并通过。正式 JAR 已核对包含新增类、28 个模型和 8 个配方，且不包含附属测试代码。

最终日志为 `build/fluid-pipes/final-batched.log`；成品为 `build/libs/mio_icif-0.1.7.14.jar`。客户端画面未人工验看，仍需在客户端确认材质显示与实际手感；服务端测试不代替客户端视觉验收。

泵覆盖板、其他覆盖板与物品管道不在本次复原范围。新管道端口开关会同步相邻管道两端，避免模型仍连接而实际不通。
