# 核电 IC2 对齐进度

日期：2026-09-29。基准：工作区 `source/IC2Code 1.12.2` 的 IC2 Experimental 2.8.221 默认行为。

用户后续优先反馈的九机冷却回路已另外定位并修复：见 [用户热核冷却液回流修复](user_reactor_coolant_loop_fix.md)。其根因是热能力适配失效；真实 4＋4＋1 锅炉布局现已通过 10000 tick 循环检查。

## 2026-10-04：按项目备份恢复事故威力，接入新的核爆效果

按用户后续要求，过热事故改用与核弹共享的新核爆表现和分批地形毁伤。基础水平半径参考 `backup/src_0.1.7.2初版`：`8 + 4 × 有效燃料单元数`；单联／双联／四联铀与 MOX 棒权重为 1／2／4，耗尽燃料不加权。垂直半径为水平半径的 70%。这一事故威力策略是项目早期实现的恢复，**不再按 IC2 原生的事故威力公式计算**；IC2 热循环、产热、寿命等既有对齐结果仍保留。

核心纯模型为 `ReactorBlastProfile`，common 世界适配器为 `ReactorBlastEffects`。倍率配置 `NuclearExplosion.reactorExplosionMultiplier` 默认 1、范围 0–16；乘以倍率及隔板两重减免后，最终威力受原有 `reactorExplosionPowerLimit` 限制，水平半径向上取整为威力的两倍。原有默认上限 45 对应水平半径最多 90 格。倍率或上限 0 暂停事故与高温环境效果；总开关关闭时仅执行局部机器事故。

过热事务固定并存档事故威力；队列满不消耗燃料，不移除反应堆，等待重试。先准入再消耗组件和移除堆芯，提交失败取消核爆及辐射区。修复过热温度超出容量时存档截断导致事故重载失败，以及 v1 存档被 v2 字段校验拒绝的问题。新增 7 项回归全部通过；全套 201 项通过 200 项，既有辐照玻璃板掉落表缺失仍未解决。以下内容为此前 IC2 对齐工作的历史记录。

### 同日后续：圆形辐射转化、植被清理与区块补处理

核弹与反应堆共享的转化半径保留为水平爆炸半径的 1.5 倍，按地表列中心到爆心的距离确定圆形范围；可转化地表及范围内树叶、花草等脆弱植被改为确定性处理。植被不掉落，含水植被保留水，实体及固体地形继续使用原压力伤害与抗爆逻辑。

`core/runtime/radiation/NuclearFalloutState` 按世界记录圆形几何及逐区块地表列完成进度，common 的 `NuclearFalloutChunkTask` 和 `NuclearFalloutManager` 使用原共享调度预算执行初次及区块加载后的补处理。不强制加载区块，保存后可以继续，不重复执行已经完成的地表列，也不重放压力伤害；待转化地形不会随整区辐射到期丢失。新核爆的持续辐射只影响已处理地表列，并保持原爆炸半径及反应堆扁平垂直几何。客户端浓雾限制到附近污染地表，切换世界重置状态。

新增 8 项辐射转化回归；历史核爆没有逐列完成记录，因此不自动重做旧版爆炸或回滚旧地形。旧存档辐射区语义保留，新核爆采用上述记录及约束。

### 2026-10-05：远距离探索的区块断层修复

后续反馈的远处及左右缺少转化，有两个调度原因：待处理队列每 tick 从相同前 32 个区块开始检查，暂不可访问的 FULL 区块长期占据队首，导致后来加载的区块饥饿；持久记录只有在整个初次地表矩形扫描结束后才允许区块加载补处理，大当量下开放得过晚。

现在不可访问区块按原预算移到队尾轮流重试；绑定持久记录的爆炸在压力毁伤结束时直接把转化交给统一的区块任务队列，避免矩形扫描及重复游标。保存的逐列进度、圆形几何、配置关闭暂停、每 tick 4096 步／2 毫秒以及最多 16 个转化任务的限制保留。

新增两项服务端回归，均在原代码下失败：模拟 64 个暂不可访问的队首区块，检查距离爆心约 1856 格的前方及左右两个方向的转化；按 8 组工业 TNT＋1 组钚计算当量 `104192`，验证最大半径任务在压力阶段结束后立即开放补处理，而不是扫描半径 3000 的整个区块矩形。修复可继续使用已有 `si_nuclear_fallout` 记录；没有该记录的历史爆炸仍不推测重做。

修复后两项新增测试及原有八项转化测试全部通过；构建和 core 边界检查通过。全量 217 项通过 216 项，唯一剩余失败仍为此前暂缓处理的掉落表问题。前后对比日志分别为 `build/fallout-routing-before.log` 与 `build/fallout-routing-after.log`；移动路径测试以区块票据模拟玩家持续视距，不强制加载不可访问的队首区块。

### 同日后续：模拟距离外的可见区块同步

用户更新并完全重启后仍有区块分界，进一步发现普通 `Level.setBlock` 在服务端只对 BLOCK_TICKING 及之后状态广播方块修改；`ChunkHolder.blockChanged` 同样只记录 ticking chunk。视距内、模拟距离外的 FULL 区块虽然已转化并记录完成，客户端却没有收到更新。之前仅检查服务端完成进度的测试没有覆盖这条链路。

新增 common 的 `NuclearTerrainUpdates`，地表转化、植被删除及压力毁伤统一接入。非 ticking 区块的修改按区块段及位置去重，打包当时的最终状态，发给实际观看该区块且已完成区块发送的玩家；每 tick 最多处理 16 个区块段，未处理记录继续保留。发送先占用原 2 毫秒共享预算的一部分，剩余时间用于爆炸任务，未扩大总时间预算。正常 ticking 区块继续使用原版同步，卸载区块的后续完整数据包负责恢复真实地形。

新增 3 项回归，其中转化与压力毁伤两项均在接入前复现客户端保留旧地形；接入后全部通过，另验证了批量包上限和合并后的最终状态。测试以 FULL 级区块票据及实际观看玩家连接捕获更新包，并应用到客户端状态记录，不再只断言服务端方块。构建与 core 边界检查通过，全量 220 项通过 219 项，唯一剩余仍为既有暂缓问题。对比日志为 `build/fallout-client-sync-before.log` 与 `build/fallout-client-sync-after.log`。

### 同日后续：核爆融雪融冰

核弹及反应堆的共用热处理 `NuclearThermalEffects` 覆盖雪层、雪块、细雪、普通冰、霜冰、浮冰和蓝冰；雪层消失，其余融水，超暖维度蒸发为空气。压力毁伤和持久地表转化同时接入，通过原客户端批量同步发送最终状态；圆形及垂直范围、关闭核爆暂停、区块补处理及已经完成列不重做的规则保留。

地表列越过冰雪后继续寻找可转化土壤；区块段快速跳过条件同时考虑植被与冰雪，避免固体覆盖下的冰层漏处理。压力前沿的近期融水位置按四个轮转缓存保存，防止重叠射线立即抹掉新生成的水，不持久保存或无限积累位置。融化不产生物品掉落。

新增四项冰雪回归，并扩展非 ticking 区块的客户端状态测试，全部通过。构建及 core 边界检查通过；全量 224 项通过 223 项，唯一剩余仍为此前暂缓的已知问题。验证日志为 `build/nuclear-snow-ice-final.log`。

## 本轮：热循环与冷凝器修复

对应 [审计报告](reactor_ic2_alignment_audit.md) 的 A1–A6、A8、A11、A13。

| 项目 | 修改后的行为 |
|---|---|
| A1 燃料分热 | 双联/四联逐燃料单元即时产热；按左、右、上、下逐接收方分配，每次将返回余量纳入下一份计算。保留原版熔毁时负余量语义。 |
| A2 MOX 与隔板 | 热阶段先执行，隔板扫描到自身时才增加容量；电力阶段用完整热阶段结束后的堆温及容量计算 MOX 增益。热核 MOX 对每个燃料单元分别判断严格大于 50% 的阈值。 |
| A3 冷媒配对 | 输入冷却液不能产入残留热水，输入水不能产入残留热冷却液。不匹配时不改动两罐，未带走的热退回堆温，燃料及元件循环继续；排空旧热媒后自动恢复。 |
| A4 散热片熔毁 | 槽位已移除的散热片在当轮仍按旧物品状态完成自冷，不复活物品。 |
| A5 增殖完成 | 达到阈值的增殖元件当轮立即停止接受后续脉冲，物品替换仍在库存原子提交中完成。 |
| A6 冷凝器换热 | 复刻原版公共读取热量为 0 的特性，并跳过已满冷凝器；内部储热没有清零。 |
| A8 工作台修复 | 青金石冷凝器每红石修复 5000、每青金石修复 40000；红石冷凝器每红石修复 10000。按格计量，每格消耗一个材料；拒绝混用红石和青金石、红石冷凝器配青金石、多冷凝器输入。补上配方 JSON，使 serializer 真正接入工作台。 |
| A11 乏燃料产物 | 铀、MOX 四联乏燃料离心均改为 7 铁粉。 |
| A13 界面单位 | 保留每 20 tick 周期实际吸收热量的数值，中英文单位改为 HU/s；不改变产热倍率。 |

对照 `ic2/core/recipe/GradualRecipe.java` 额外确认：原版允许未储热冷凝器参与补充配方，且红石、青金石为独立配方，不能混合。本轮也遵循这两点。配方输出复制物品及其组件，不修改输入堆栈。

`core` 仍只包含独立数值模型；流体种类配对由 `common` 判断，以布尔参数传入核心模型。原有 `FluidReactorCycle` 方法签名保留，新增重载承接兼容性判断。现有注册 ID、存档字段及燃料剩余寿命保持兼容。
