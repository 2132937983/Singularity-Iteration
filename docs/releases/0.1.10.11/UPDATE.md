# 0.1.10.11 更新说明：剑模型、创造模式发电机、区块加载器管理与僚机修正

基于 0.1.10.10（`pr-0.1.10.10-20261019`）。共 10 项。构建环境为 Gradle 8.10.2、JDK 21、NeoForge 21.1.218，离线构建。

## 1. 纳米剑与量子剑手持时的紫黑格子（缺失模型）

* 原因：两把剑的 3D 模型含有 1.21.1 模型加载器不接受的元素旋转（纳米剑一个 `x:-50` 的自由旋转，量子剑两个同时绕 x 与 z 的旋转）。加载器拒绝整个模型，手持时显示缺失模型；物品栏中由外层包装模型改显示 png 图标，因此看不出问题。
* 修复：这些元素改为合法的单轴旋转（纳米剑 x -45°，量子剑 x 45°），外观差异极小。量子剑两种形态新增自己的 GUI 变换。

## 6. `models/item/3d` 的 JSON 全部移到 `models/item`

* 29 个模型从 `models/item/3d` 移到游戏实际读取的路径，替换原来的 `neoforge:separate_transforms` 包装模型（包装模型在 GUI 中改用 png，覆盖了模型自己的 GUI 设置）。包装模型的 `overrides`（例如纳米剑开关状态）保留在新模型中。`3d` 文件夹已删除，贴图仍在 `textures/item/3d`。
* 武器：`item_tool_nanosaber`、`item_tool_nanosaber_active`、`item_tool_quantum_sword`、`item_tool_quantum_sword_hyper`；护甲模型（`builtin/entity`）现在在物品栏中也显示 3D 套装部件（`BakedArmorItemRenderer`，使用模型自己的 `gui` 变换）。
* 注意：旧的一次性工具（`intake_swords_1104.py`、`item_models.py` 等）仍按 `3d` 布局写出模型，再次使用前需要调整。

## 2. 冷却液注入器界面标题重叠

* 青金石／红石冷却液注入器：方块数量原先画在 (28, 6)，与居中的标题重叠（例如“青金石冷却液注入器”看起来像两层字）。数量行移到注入器槽位与玩家物品栏之间的空行，并限制宽度。标题恢复单独显示。

## 3. 调试用“创造模式发电机”

* 新方块 `mio_icif:generator/block_creative_generator`（创造模式物品栏“发电机”分组，无配方）。
* 仅限创造模式：只有创造模式玩家能放置；生存模式无法挖掘、抗爆、不掉落；只有创造模式玩家或管理员（权限等级 2）能打开界面。
* 输出可自由设定：0 至 1,000,000,000,000 EU/t。输入框支持千位分隔与 k／M／G／T 后缀（如 `2.5M`）；预设 32～1M；x10、/10；开关。界面显示上一 tick 实际送出的 EU。
* 忽略电压与电流限制、不过载：每 tick 以一个包含全部输出的数据包向六个面输出（无等级上限）；新 API `IOverloadFreeEnergySource` 使电网对其输送不触发导线熔断、绝缘击穿、电击与接收端爆炸。接收端仍只接收其空间与额定输入允许的电量，导线损耗照常。
* 无限发电机保持原样（固定 8,192 EU/t，正常过载规则）。

## 4. 装罐机液体的进入储罐

* 原因：装罐机的流体弹出升级向相邻的另一台装罐机弹出时，端口选反了，液体进入了对方的右侧（输出）储罐。
* 修复：弹出进入相邻机器的输入端口（装罐机为左侧储罐），抽入从相邻机器的输出端口取出。管道、泵等外部注入原本就进入左侧储罐。
* 说明：“排空到储罐”模式下，从流体单元倒出的液体进入右侧储罐，这是 IC2 的设计，不变。

## 5. 区块加载器的服务器管理优化

性能：
* 每台加载器此前每 tick 调用 `setChanged()`（通知 6 个邻居）、两次复制选择集合并重新扫描升级槽。现在稳定状态只扣除电量：票据只在授予的区块变化时调整，规则每秒复查一次（变化后立即），升级只在物品栏变化后重算，不再每 tick `setChanged()`。

服务器规则（配置 `ChunkLoaders` 节，可热重载）：
* `enabled`：总开关，关闭后所有 SI 加载器释放区块（保留选择）。
* `maxChunksPerLoader`（1～25）、`maxChunksPerPlayer`、`maxLoadersPerPlayer`（0 = 不限）：超出时优先保留自身区块，其次是最近的已选区块；玩家额度先到先得、跨维度合计。
* `offlineOwnerMinutes`：所有者下线后继续工作的分钟数（-1 = 一直工作，默认，与之前相同；0 = 立即停止）。
* `euPerChunkPerTick`：每区块每 tick 的 EU（默认 1）。
* `randomTicks`：关闭后，已加载区块不进行随机刻与自然生成，机器、方块实体与实体照常运行，开销小得多（默认开启，与之前相同）。
* `ownerOnlyEdit`：仅所有者与管理员可修改区块选择。
* 所有者：放置加载器的玩家（0.1.10.11 之前放置的加载器没有所有者，不受玩家规则影响）；用扳手拆下再放置时，放置者成为新所有者。
* 因规则停止的加载器连同自身区块一起卸载，原因消除后自动恢复：所有者上线、管理员重新启用、开关重新打开、额度释放。名单保存在主世界存档中。

管理命令（权限等级 2）：
* `/mio_icif chunkloaders`：总数、规则与每台已加载的加载器（维度、坐标、所有者、已授予／已选区块、状态），以及等待恢复的加载器；点击坐标可填入传送命令。
* `/mio_icif chunkloaders player <名称>`、`disable <坐标> [维度]`、`enable <坐标> [维度]`、`disable_all`（紧急停止全部）。管理员停用随加载器保存。

界面：地图上方的红色横条说明加载器没有加载（全部）区块的原因；鼠标移到区块数上显示状态与已加载／已选／上限。

## 7. 僚机待机时着地

* 没有目标 2 秒且主人站在地面上时，僚机降落到身旁的地面并关闭推进器，以站姿待机。驻守命令的地点也会着陆。
* 出现目标或命令、主人走开 3.5 格以上、飞行或滑翔时立即起飞。水面、岩浆或 8 格内没有地面时不着陆。

## 8. 僚机持拔刀剑时手部抖动

* 原因：SlashBlade 的刀由其自己的动作骨骼相对身体绘制，不跟随手臂；而僚机的手臂与前倾角按上一 tick 的原始速度每 tick 跳变，持刀连段又每 5 tick 重新开始原版挥臂动画，手与刀之间出现抽动。
* 修复：飞行系数与着陆过渡按 tick 平滑并按帧插值；持刀时手臂保持静止的架势，不再叠加摆动；刀的连段不再调用原版挥臂。

## 9. 僚机拔刀剑攻击时不播放挥刀动作

* 每次斩击同步到客户端（计数与种类），手臂播放对应动作：连段为斜斩，突进为水平横扫，SA 为双手下劈。
* 连段输入改为每 8 tick 一次（此前 5 tick，每段动作被下一次输入打断），每一刀都完整播放。

## 10. 采矿镭射“超高能爆破模式”的专用特效

* 不再显示原版爆炸烟团与原版爆炸声：新的等离子爆破特效包括白热核心（逐渐冷却为青色、紫色）、等离子光柱、两道贴地冲击环、球形冲击壳、监守者音爆环、放射状火花与持续的电弧、余辉与上升的离子雾、烟柱。看见爆心的玩家有白色闪光，冲击波以每 tick 5 格到达时镜头震动（分别受“核爆闪光”“镜头震动”选项控制），粒子数量随粒子设置。
* 新音效 `weapon.laser.ultra_blast`（合成：充能爆裂、等离子爆裂、低频冲击、电弧嘶嘶声与长尾隆隆声）。
* 爆炸本身（伤害、地形、保护模组事件、配置开关）不变。
