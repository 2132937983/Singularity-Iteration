# 0.1.10.17 更新说明：同步瘦身（E-2）——更新标签只发送客户端读取的数据

基于 0.1.10.16。共 5 项。构建环境为 Gradle 8.10.2、JDK 21、NeoForge 21.1.218，离线构建。

## 背景

方块实体的更新标签（`getUpdateTag`）有两条发送途径：

* 区块加载：玩家开始追踪一个区块时（进入视距、传送、重新登录），该区块中每个方块实体的更新标签都随区块数据包发送。客户端用 `handleUpdateTag` 应用。
* 方块实体数据包：只有覆盖了 `getUpdatePacket` 的方块实体才会发送。`sendBlockUpdated` 与方块状态变化都会触发。客户端用 `onDataPacket` 应用。

两者的原版默认实现都对收到的标签执行完整的 `loadAdditional`（NeoForge 21.1.218 的 `IBlockEntityExtension`）。

调查结果（172 个方块实体类）：

* 15 个类的更新标签直接使用完整存档（`saveWithoutMetadata` 或 `saveAdditional`），其中 4 个还会发送方块实体数据包（EU 分流／检测导线、变压器、能量转换器、作物），其余 11 个只在区块加载时发送。
* 加工机器、储电设备、发电机、加热机、动能发生机 5 个预制基类（约 80 个类）把整个库存放进更新标签。
* 客户端读取方块实体数据的代码：方块实体渲染器（作物、转子、展示台、武装库、改造台、建造机、树脂收集器、伪装、无线节点、采矿机范围、激光塔）、Jade（使用服务器数据）、电压 HUD（只检查类型，数值来自服务器）、界面（数据来自菜单同步：`ContainerData` 与原版槽位同步）。没有代码在菜单之外读取上述机器的库存或储罐。

## 1. 15 个完整存档的更新标签

| 方块实体 | 0.1.10.17 的更新标签 |
|---|---|
| 冷凝机、电解机、精炼机、泵、复制机（加工机器基类） | 父类的客户端数据（能量、进度、工作状态） |
| 核反应堆（发电机基类） | 父类的客户端数据（能量、燃烧时间） |
| 流体加热机、热交换机、固体加热机、发酵机（热能基类）、太阳能蒸馏机 | 空标签（父类没有客户端数据） |
| EU 分流／检测导线 | `active` |
| 变压器 | `mode`、`active` |
| 能量转换器 | 父类的客户端数据与 `Mode` |
| 作物 | 存档去掉 `Progress`、`CropTicker`、`FertilizerCooldown`、`TendedUntil`、`CropCycleVersion` |

* 只在区块加载时发送的 11 个类：客户端收到标签时方块实体是新建的，缺失的键只让客户端从不读取的字段保持默认值。
* 发送数据包的 4 个类：标签保留客户端读取的全部键；缺失的键只影响服务器数据（导线的轮询相位、变压器的缓存能量、转换器的 FE 储量）。
* 作物：渲染器读取植物与生长阶段，亮度与附属模组植物可能读取性状、资源、扫描等级、杂交与 `CustomData`，因此这些都保留；扫描仪 HUD 的读数来自服务器（`CropScannerPacket.HudRequest`）。

## 2. 预制基类不再发送库存

* `AbstractProcessingMachineBlockEntity`、`AbstractEnergyStorageBlockEntity`、`AbstractGeneratorBlockEntity`、`AbstractHeatGeneratorBlockEntity`、`AbstractKineticGeneratorBlockEntity` 新增 protected 方法 `syncInventoryToClient()`，默认 `false`；只有返回 `true` 时更新标签才包含库存（`inventory` 或 `Items`）。
* 柴油发电机、地磁发电机与物品分配机此前自己再写一次库存，现在同样不发送。
* 安全性：
  * 界面不受影响：菜单打开时，原版把所有槽位的物品发送给客户端。
  * 5 个基类的 `loadAdditional` 与 `handleUpdateTag` 都只在标签含有库存时才应用（`tag.contains`），因此不含库存的标签不会清空客户端的物品，打开的界面也不会突然变空。
  * 风力／水力动能发生机的更新标签仍包含转子（渲染器绘制转子），它们使用自己的紧凑标签。
* 附属模组：若方块实体渲染器等客户端代码读取物品，请覆盖 `syncInventoryToClient()` 返回 `true`（API 指南第 19 节）。
* 创造模式下按住 Ctrl 选取方块时，客户端复制的方块数据不再包含库存（与原版箱子相同）。

## 3. 隐私

核反应堆的完整存档包含事故调查的所有者 UUID 与名称（`AuditOwner`、`AuditOwnerName`），泵的完整存档包含动作所有者（`ActionOwner`）。此前它们随更新标签发送给附近的所有玩家；现在只保存在服务器上。

## 4. 精炼机界面

`OilRefineryElcMenu.getInputFluid()` 与 `getOutputFluid()` 此前优先读取客户端方块实体的储罐。精炼机不发送方块实体数据包，客户端的储罐只有区块加载时的数据，所以界面显示的流体与数量可能是过时的。现在两者都取自菜单同步数据（流体 ID 9／10，数量 5／7），与泵和热交换机相同。

## 5. 估算与测试

用实际的键名与典型状态估算更新标签（未压缩的二进制 NBT，`work-1117/tag_size_model.py`）：

| 情况 | 0.1.10.16 | 0.1.10.17 |
|---|---|---|
| 粉碎机（矿石、粉、电池、3 个升级） | 642 字节 | 134 字节 |
| MFSU（量子胸甲与电池） | 433 | 94 |
| 核反应堆（54 个部件） | 6,958 | 112 |
| 发酵机（两个储罐与 3 个物品） | 488 | 2 |
| 作物（每次可见变化发送） | 301 | 199 |
| 变压器（切换模式时发送） | 71 | 23 |
| EU 分流导线 | 52 | 12 |

区块数据包超过 256 字节时会被压缩，实际网络节省小于上表。真实大小由 GameTest `Round1117GameTests.updateTagsCarryNoInventory` 在游戏中写入日志（每个 SI 方块实体的更新标签与存档大小）。

## 未修改的发现

* 传送机的客户端粒子读取 `isActive` 与 `cooldown`，但这两个值只在存档中，不在更新标签中，客户端从未收到，因此粒子不会显示（0.1.10.16 及以前相同）。修复需要新增同步。
* `ClientSyncThrottle.request` 用于热交换机、储物箱、柴油发电机、物品分配机与流体分配机，但这些方块实体没有 `getUpdatePacket`，请求只发送方块更新，不带方块实体数据。

## 存档与兼容

* 存档格式不变（只改变发送给客户端的数据）；没有新增或删除的注册项；语言文件不变。
* 公开 API：5 个预制基类各新增一个 protected 方法，没有删除的成员。
* 未在游戏内确认：各界面、渲染器与 Jade 的显示（按调查结果不受影响）、`Round1117GameTests` 的实际大小。
