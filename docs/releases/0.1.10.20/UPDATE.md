# 0.1.10.20 更新说明：核心系统改进第一阶段（期货 M1、电网 G1/G2、火控 P1/P3/P8）

基于 0.1.10.19。依据方案 `work-1120/SI_core_systems_proposal_ja.md`，按用户指定的顺序实施：期货 M1 → 电网 G1/G2 → 火控 P1/P3/P8。构建环境为 Gradle 8.10.2、JDK 21、NeoForge 21.1.218，离线构建。

## 1. 期货机 M1：每人上限、价差、市场每日收购额度

### 问题（代码中确认）

* 每日交易上限（`maxDailyItems`，默认 100）是每台期货机的字段 `dailyTradeVolume`。放置 N 台机器，上限就是 N 倍。
* 换日时只有执行换日的那台机器清零自己的计数；其他机器只同步天数，计数停留在前一天，达到上限后就一直无法交易。
* `FutureMarketData` 存在各维度自己的存储里：下界、末地或空间站中的期货机是另一个市场（另一套价格、天数与历史），也是另一份上限。
* 买入价与卖出价相同，价格每日均值回归。暴跌后买入、回升后卖出没有任何成本，可以无风险地产生货币。
* 市场无限收购：可再生的农产品可以无限卖给市场。
* 打开界面时，菜单每 tick 把一名查看者的金币数写入机器、标记已修改并发送方块更新；多人同时查看时，所有人看到的都是同一个人的金币与机器的计数。

### 修改

* 市场全服唯一，存于主世界（`FutureMarketData.get` 总是使用主世界存储）。其他维度旧的市场数据不再读取，那些机器改为显示全服市场。
* 每日计数按玩家 UUID 统计，全服所有期货机共享，随市场换日清零（`getPlayerVolume`、`addPlayerVolume`）。
* 价差（新配置 `spread`，默认 0.06）：买入 = 价格 × (1 + 价差/2)，卖出 = 价格 × (1 − 价差/2)，按整笔交易的总额取整（买入向上、卖出向下）。
* 市场每日收购额度（新配置 `systemBuyPerDay`，默认 256 个/货品/天，0 = 不限）：全体玩家合计。额度使用过程中卖价逐个线性下降，到额度末尾时降低 `budgetPriceDrop`（默认 0.3）。超过剩余额度的出售会被拒绝。
* 纯计算放在 `common.future.MarketQuote`。
* 界面：显示当前数量的买入总价、卖出总价与今日剩余收购量；金币数与今日交易量按查看者显示（`viewerData`）；不再每 tick 发送方块更新。
* 交易失败时在动作栏显示原因：今日上限、未选择货品、货币不足、物品不足、电力不足、背包已满、市场今日已满。

### 数值（离线测试）

* 64 个、价格 100：买入 6,592，卖出 6,208（无额度）。
* 额度 256、降幅 30%：第一批 64 个卖 5,975，最后一批 64 个卖 4,578。
* 每种货品每天最多产生约 21,106 货币（价格 100 时），整体有上限。
* 局限：价格大幅下跌后买入、回升后卖出仍有利润（价格回归本身没有改变；−50% 时每 64 个从 3,200 降为 2,679），但受到每人每日上限与市场收购额度的约束。要彻底消除，需要方案中的 M2（国库库存：市场只出售自己收购的库存）。

## 2. 电网 G1：按连通块保存导线图（结果不变）

### 问题

`ConductorRegistry.snapshot()` 是整个维度的一张图：

* 任何位置的一次编辑（放置、拆除、面掩码变化、区块加载/卸载）都会把维度内所有导线重新排序、建立索引与连接，并构建 `ConductorGraph`（O(N log N)）。
* 新快照的身份变化使全维度所有路由视图与计划缓存失效，路由搜索缓存也全部丢弃。

在多人服务器的主世界，一个人放一根导线，所有人的电网都要重新规划。

### 修改

* 注册表持续保存每个连通块的图（位置、局部编号、面掩码、`ConductorGraph`）。
* 编辑只标记被编辑的位置及其 6 个相邻位置。下一次 `snapshot()` 只拆除并重建包含这些位置的连通块（广度优先搜索沿用原来的连接规则；遇到未拆除的连通块时合并）。
* 快照是各连通块的组合视图：
  * 连通块按最小位置排序。
  * 每个连通块内的顶点按位置升序编号，因此同一连通块内顶点的相对顺序与旧的全局编号相同，路由搜索选择的路径（包括等价路径）与之前完全一致。
  * `componentOf` 仍是该连通块的最小顶点编号。
* 路由搜索缓存改为跨所有连通块的一个 LRU（沿用原来的源数与路由顶点数上限）。未变化的连通块的缓存跨快照保留。
* 快照仍会因任何编辑失效，所有租约检查不变。引擎代码未修改。

### 验证（`verify-si1120`，离线）

* **等价性**：40 个随机网络（多个相距较远的基地，随机放置、拆除、修改损耗与面掩码、区块启用/停用、卸载），共 6,008 个快照与 0.1.10.19 的实现逐项比较。比较项：包含关系、面掩码、连通块大小、搜索权重、连通块划分、抽样源到每根导线的可达性与损耗，以及路径的逐格顺序与顶点数。约 466 万项检查，全部一致。
* **时间**：101,970 根导线、50 个基地，在一个基地旁放一根导线后的快照：旧 182 ms，新约 2 ms（20 次平均）。只重建 1 个连通块，其他基地的路由搜索缓存保留。

## 3. 电网 G2：稳态窗口重放（结果不变）

* 公平分配（默认模式）中，一个窗口的分配是其输入的纯函数。输入为：
  * 各源的预算、包大小、类别；
  * 各接收方的空间、额定输入、类别、中继需求；
  * 共享储能；
  * 线损模式；
  * 每个类别的轮转起点（`rotation mod 数量`，见 `FairShareDistributor.sourceOrder`）。
* 公平模式下的分组只取决于路由计划和哪些预算为零。
* 稳定运行的工厂每 tick 输入相同。路由计划按轮转起点保存最近的分配（每个计划最多 8 个）；输入相同时复用分组与分配结果，跳过分组构建与水位分配。
* 提交、提交前验证、路径效果与仪表采样仍每 tick 执行。
* 离线验证：400 个随机窗口（最多 32 个源、128 个接收方，含储能、额定输入、中继需求）。
  * 分配是确定的，轮转起点相同时结果相同。
  * 81% 的窗口结果依赖轮转起点，因此重放的键包含它。
  * 输入比较的耗时约为分配的 1/25。
* `/mio_icif perf` 新增一行：编辑后重建的连通块、最近重建时保留的连通块、重放的稳态窗口（`IndependentSiEnergy.gridReuseCounters()`）。

## 4. 火控 P1/P3/P8

纯计算放在新包 `common.fcs`（不依赖 Minecraft，可离线测试）。

### P3 射击解（HUD 的“LEAD”菱形）

* 此前的菱形是目标在一段飞行时间后的位置。飞行时间按水平距离计算一次，不含重力与所需仰角；目标速度是一个 tick 的位移。
* 现在 `Intercept` 用火控的瞄准点迭代：
  1. 朝瞄准点发射；
  2. 按原版顺序（移动、阻力、重力）模拟弹道；
  3. 找到与目标预测位置的最近点；
  4. 按偏差移动瞄准点；
  5. 外层循环把目标位置更新到最新的飞行时间。
* 计入重力、阻力、玩家自身速度与飞行期间目标的移动。用上一 tick 的解热启动，通常每 tick 1 至 3 次模拟。
* 菱形画在发射方向上，把准星放在菱形上即可命中。
* 离线（满弓，目标横穿或接近）：

| 距离 | 旧偏差 | 新偏差 |
|---|---|---|
| 15 m | 0.6 格 | ≤ 0.09 格 |
| 30 m | 2.5 格 | ≤ 0.09 格 |
| 45 m | 5.8 格 | ≤ 0.11 格 |
| 60 m | 10.4 格 | ≤ 0.07 格 |

* 冷启动一次约 14 µs。
* 与方案的差异：没有预先计算二维射表。弓的速度在拉弓过程中连续变化，每种速度都需要一张表，在客户端帧内构建会卡顿；热启动的数值解精确且只需微秒。

### P1 目标运动估计（`TargetTracker`）

* 速度仍为最近三步的平均。测试了 α-β 与 α-β-γ 滤波器：客户端以 3 tick 的直线段插值实体位置，三步平均正好匹配这一运动；没有任何滤波器在直线、之字形、绕圈、起停、随机游走五种运动中整体更好，加速度项反而使 1 秒预测摆动。
* 新增协调转弯模式（IMM 中的 CT 模型）：
  * 取最近 6 组 3 tick 弦之间的航向变化率；
  * 一致（标准差 ≤ 0.004 rad/tick）且平均 ≥ 0.01 rad/tick 时，按圆弧预测；
  * 单次转向在 6 组弦上不会一致，因此之字形与随机游走仍按直线预测。
* 1 秒预测误差：绕圈 2.78 → 0.14 格，其他运动不变（直线 0、之字形 4.16、起停 1.51、随机 0.80）。
* 行为预测器的轨迹也按转弯率弯曲，提前量目标使用同一估计。

### P8 预测轨迹的开销

* `DeadReckoning`：规则与 0.1.7.36 相同。
* 方块查询按方块格在一个 tick 内缓存，所有轨迹共享。
* 轨迹每 2 tick 重算，中间随生物平移。
* 离线：30 个生物 200 tick，世界查询 117,084 → 16,036 次（约 7.3 倍），轨迹完全相同。
