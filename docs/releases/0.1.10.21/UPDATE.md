# 0.1.10.21 更新说明：核心系统改进第二阶段之一（期货 M2～M5：国库、盘口与委托、自动上市、数据面板）

基于 0.1.10.20。依据方案 `work-1120/SI_core_systems_proposal_ja.md` 的第二阶段，本版本完成期货交易所部分（M2～M5）；电网 G3～G7 与火控 P2、P4～P7 在后续版本。构建环境为 Gradle 8.10.2、JDK 21、NeoForge 21.1.218，离线构建。

期货机从“按当日价格与系统买卖”变为全服一个交易所（存档数据 `mio_icif_exchange`，存于主世界）。所有期货机都是它的终端。

## 1. 国库（M2）

### 问题

0.1.10.20 之后，市场仍然可以无限出售：价格暴跌后从市场买入、回升后卖回，利润只受每人每日上限与收购额度限制（方案中的已知局限）。

### 修改

* 市场收购的物品进入国库。市场只出售国库库存，以及每种货品每天少量的进口（`importPerDay`，默认 64 个），进口价格另加 `importPremium`（默认 10%）。
* 市场委托：每天换日时，市场为库存不足 64 个的货品（不含需要进度解锁的货品）发布委托，同时最多 `systemCommissionsPerDay` 个（默认 3）。数量 32～128 个，报酬为市场买入价的 1.15 倍，期限 3 天。报酬是新发行的货币，交付的物品进入国库。
* 市场委托开放期间，市场不出售该货品。否则从市场买入、再交付给市场委托，就能赚取 15% 的差价（玩家的挂单照常成交）。
* 账本：记录每天发行的货币（市场收购、市场委托报酬、期货盈利）与销毁的货币（市场出售、手续费、期货亏损），保留 60 天，显示在“国库”页。
* 新界面使用下单面板（第 5 节）。服务器保留原来菜单的买入/卖出按钮编号（交易数量），改为下即时订单：
  * 先与玩家的挂单成交，再与市场成交。
  * 买入的价格上限为市场报价的 1.1 倍，卖出的价格下限为市场的收购报价。
  * 未成交的部分不保留。

## 2. 盘口、邮箱与委托（M3）

### 订单

* 限价订单，有两种方式：
  * “即时”：立即成交，未成交部分取消。
  * “挂单”：未成交部分在盘口保留 7 天。
* 成交规则：
  * 价格优先、时间优先。
  * 同一玩家或同一队伍的订单之间不成交（自成交只会抬高或压低价格）。
* 托管：
  * 买单冻结“限价 × 数量”的货币（或 UU 物质）。
  * 卖单冻结物品，只接受没有附加数据的普通物品（耐久、附魔、自定义数据的物品通过委托交易）。
* 成交价为挂单方的价格，买方多冻结的部分退回。
* 卖方支付手续费 `exchangeFee`（默认 1%），手续费销毁。
* 限制：
  * 每人最多 32 个挂单，每笔最多 1,024 个。
  * 价格区间：数据包货品为基础价格的 `minPriceMultiplier`～`maxPriceMultiplier` 倍；玩家上市品为基本价值的 0.5～3 倍（没有 UU 价值时不限）。
* 即时订单没有任何成交时，显示“限价内没有可成交的对象”，不扣电力。

### 邮箱与 UU 账户

* 邮箱保存交易所欠玩家的东西：挂单成交所得（离线时也会成交）、撤单退款、背包放不下的物品与货币。在“挂单与邮箱”页领取；UU 物质留在账户中。
* UU 账户（mB）：
  * 存入：清空背包中装有 UU 物质的容器（桶、单元、通用流体单元），空容器退回。
  * 取出：只填充空容器或装有 UU 物质的容器，不会新建容器。

### 委托

* 报酬可以是：
  * 货币：手续费为报酬的 2%，销毁。
  * 物品：手续费 5 货币。
  * UU 物质（从账户支付）：手续费 5 货币。
* 报酬在发布时托管。可以部分交付，按比例支付；交付的物品进入委托人的邮箱。
* 不能交付自己的委托。
* 限制：每人最多 8 个，全服最多 512 个，期限 1～7 天。
* 过期或撤回时，未支付的报酬退回委托人的邮箱，手续费不退。

## 3. 自动上市与货币区分（M3）

* 上市证据：结束时至少有一次交付的委托，记录委托人、交付者、日期，以及货币报酬的单价。委托人在发布时的游戏时间不足 `listingMinPlayMinutes`（默认 120 分钟）时，这个委托不计入（防止小号）。
* 多人：7 天内同时满足以下条件时上市：
  * 至少 `listingRequesters`（默认 3）名不同的委托人；
  * 至少 `listingFulfilled`（默认 3）个完成的委托；
  * 交付者合计至少 2 人。
* 单人（集成服务器）：在不同的日期完成 `listingFulfilled` 个委托。注意：纯单人时没有其他玩家可以交付（自己交付会被拒绝），因此需要局域网等其他玩家。单人的交易所主要由市场、市场委托与期货组成。
* 初值：
  * 货币单价的稳健中位数（去掉偏离中位数 3 个 MAD 以上的值），再限制在基本价值的 0.5～3 倍之内。
  * 没有货币报酬时使用基本价值。
  * 既没有货币报酬也没有 UU 价值的物品不上市（只能委托）。
* 基本价值：物品的 UU 价值（桶）乘以每桶 UU 物质的货币价值。每桶的货币价值是所有数据包货品“基础价格 ÷ UU 价值”的中位数。
* 货币：合成深度达到 `uuDepth`（默认 3）的物品以 UU 物质（mB）交易，其余以货币交易。
* 合成深度：
  * 由服务器的全部配方计算：合成、熔炼与机器配方。
  * 物品的深度 = 最浅配方的原料深度 + 1。
  * 只由配方循环产生的物品（例如粗铁与粗铁块）视为原料，深度为 0。
  * 没有物品原料的配方（作物、流体）不计入。
  * 重新加载数据包后重新计算。
* 下市：30 天没有成交且没有挂单时下市。数据包货品不会下市。
* 上市时向全服广播。

## 4. 期货（M5）

* 3 天或 7 天的现金结算合约，只针对数据包货品。
* 全额保证金：合约价格 × 数量。到期时按当天的市场价格结算：
  * 多头收回 `min(结算价, 2 × 合约价) × 数量`；
  * 空头收回 `(2 × 合约价 − min(结算价, 2 × 合约价)) × 数量`。
  * 因此最多亏损全部保证金，最多盈利一倍保证金，不会违约。
* 结算款进入邮箱。每人最多 8 份未结算合约。

### 定价：模拟市场自己的价格模型

* 市场是对手方：任何一方有正的期望收益，都等于凭空发行货币。
* 合约价格由蒙特卡罗模拟决定：8,000 条路径，种子按货品与日期固定，同一天内报价不变。模拟使用与市场相同的规则：
  * 当前事件继续；
  * 没有事件的日子以 20% 的概率产生新事件；
  * 随机步、均值回归与向下取整；
  * 调价周期（`period_days`）。
* 在这些路径上求两方的盈亏平衡价，然后多头加一半价差，空头减一半价差。
* 修正的问题：最初的实现按均值回归预测的远期价格定价。离线测试发现：
  * 每天的价格向下取整（平均约 0.5），使空头期望为正：每 64 份最多 +165 货币。
  * 在上涨趋势事件中，多头每 64 份最多 +8,640 货币。
  * 情报物品（`mio_icif_intelligence`）会显示当前事件，所以这是确定的获利方法。
* 新定价下，两方在所有测试情形中的期望均为负（独立路径验证，见第 8 节）。
* 价格模型移到 `common.future.FuturePriceModel`：机器的调价与事件生成使用同一代码，行为不变。事件新增带随机源参数的 `applyEffect` 重载，模拟使用自己的随机源。
* 已知：期货报价反映当前事件的预期（例如上涨趋势中多头报价更高），玩家可以从中推测事件。现货交易仍受每人每日上限、收购额度与国库库存的限制。

## 5. 数据面板（M4）

期货机的界面换成全屏数据面板，分为 5 页：

* **行情**：
  * 左侧：自选列表，显示价格、涨跌、最近 20 天的走势线和今日成交量；未解锁的货品变暗，玩家上市品标记为 P。
  * 中间：日 K 线与成交量、5 日均线、基本价值虚线；市场报价（卖价、库存与剩余进口、收购价、剩余收购额度、本人今日剩余交易量、价格区间）；最近成交（自己的成交高亮）。
  * 右侧：盘口深度（点击档位填入价格）与下单面板（买入/卖出、即时/挂单、限价、数量、合计）。
* **委托**：委托板（交付、撤回）。发布表单：点击背包中的物品选择需求物品与报酬物品，填写数量、报酬种类与金额、天数，并显示手续费。下方显示各物品的上市进度。
* **期货**：所选货品 3 天与 7 天的多空价格、两种合约的保证金和说明，以及持仓（当前价值与剩余天数）。
* **挂单与邮箱**：自己的挂单（撤单）、邮箱（领取）、UU 账户（存入、取出）。
* **国库**：14 天的发行与销毁柱状图及合计、国库库存、玩家上市品数量。

其他行为：

* 界面打开时每秒请求一次视图。
* 每个操作是一个数据包，服务器重新检查全部规则：
  * 界面必须打开，机器必须在 8 格之内；
  * 速率限制 `exchange`：最多连续 12 次，之后每 4 tick 恢复 1 次；
  * 每个成功的操作消耗一次交易的 EU，失败不扣。
* 视图数据有长度上限，超过上限的数据包会被拒绝。

## 6. 管理命令

`/mio_icif market audit [组数]`（权限等级 2）显示：

* 玩家上市品、挂单、委托、未结算期货与保证金的数量；
* 最近 7 天发行与销毁的货币；
* 最近 7 天互相交易量最大的玩家组合（默认 5 组，最多 20 组）：数量、笔数、金额，以及占玩家之间成交量的比例。

某一组合远超其他组合时，值得检查（刷量、账号之间转移）。

## 7. 配置（`FutureMarket` 分类）

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `exchangeFee` | 0.01 | 玩家之间成交的手续费（卖方支付，销毁） |
| `importPerDay` | 64 | 每种货品每天的进口量 |
| `importPremium` | 0.1 | 进口品的加价 |
| `listingRequesters` | 3 | 上市所需的不同委托人数（多人） |
| `listingFulfilled` | 3 | 上市所需的完成委托数（单人：不同日期） |
| `listingMinPlayMinutes` | 120 | 委托计入上市证据所需的游戏时间（分钟） |
| `uuDepth` | 3 | 以 UU 物质交易的合成深度 |
| `systemCommissionsPerDay` | 3 | 市场同时开放的委托数 |

## 8. 验证

* 离线测试 `verify-si1121`（55 项，全部通过）：
  * 盘口：价格时间优先、部分成交、限价、自成交与同队成交的阻止、撤单、深度。
  * 估值：稳健价格、区间限制、校准。
  * 上市规则：证据条件、合谋时的初值限制、单人按日期计数。
  * 合成深度：包括配方循环与超过计算轮数的长链。
  * 期货（每种情形 40,000 条独立路径，每 64 份的平均收益）：
    * 普通价格模型：开始价格 15～600、3 天与 7 天，两方都为负，最好的一方 −66；旧定价的空头 +165。
    * 带趋势事件的模型（包括处于强上涨趋势中）：两方都为负，最好的一方 −45；旧定价的多头最多 +8,640。
  * 多空合计的结算不超过两份保证金。
* GameTests：`Round1121GameTests`（6 项）：
  * 两名玩家之间的上市品交易：托管、手续费、自成交、撤单、审计；
  * 市场委托：停止出售、国库与账本；
  * 期货保证金与同日报价不变；
  * 存档数据的保存与读取；
  * 视图编解码（拒绝超长数据）；
  * 合成深度。
* 检查工具 `check_1121.py`。
