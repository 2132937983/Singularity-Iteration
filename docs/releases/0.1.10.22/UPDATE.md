# 0.1.10.22 更新说明：核心系统改进第二阶段之二（电网 G3 经济次序、G4 负荷优先级、G5 保护、G7 监控面板）

基于 0.1.10.21。依据方案 `work-1120/SI_core_systems_proposal_ja.md` 的第二阶段，本版本完成电网部分：G3、G4、G5、G7。G6（导线载流量与发热）按方案为可选项，未实施。火控 P2、P4～P7 在下一版本。构建环境为 Gradle 8.10.2、JDK 21、NeoForge 21.1.218，离线构建。

## 1. G3：经济次序（电源调度）

### 问题

公平分配中，所有发电机（太阳能、核能、燃料发电机）与变压器同属一类，按轮转顺序供电，储能最后。

* 燃料发电机经常在太阳能还有余量时供电；太阳能没有缓存，多余的电直接损失。
* 燃料发电机只在能量被取用时才消耗燃料（满缓存时停止燃烧），所以这些燃料本可以节省。

### 修改

* 发电机的调度类别（新公共 API `core.api.energy.grid.DispatchClass` / `IGridDispatch`）：
  * `MUST_RUN`：太阳能、风力、水力、动能、地磁、放射性同位素、核能等，不取用就损失。
  * `DISPATCHABLE`：火力（燃料）、地热、半流体、柴油、斯特林（两种）、经验、掉落物（各两种）发电机，不取用时燃料留在机器中。
  * 未声明的发电机视为必须运行（与之前相同）。
* 新配置 `EnergyNet.dispatchMode`（`core.ini` 中为 `energynet.dispatchMode`）：
  * `merit`（默认，经济次序）：必须运行的电源与变压器 → 燃料发电机 → 储能。燃料仍为储能充电。
  * `economic`（经济调度）：必须运行的电源与变压器 → 储能 → 燃料发电机。燃料不为储能充电，储能只由盈余充电。
  * `rotation`：0.1.10.22 之前的次序。
* 实现：`FairShareDistributor` 的源增加“次序”（每个阶段内按次序访问，同一次序内轮转）与“是否为储能充电”。次序等于类别、全部充电时与之前完全相同。
* 稳态窗口重放（G2）的键改为每个次序的轮转起点。

### 数值（离线测试，20 个昼夜）

条件：白天太阳能 100 EU/t，燃料发电机最多 128 EU/t，储能容量 200,000（初始 50%），负荷 80 EU/t。

| 模式 | 燃料消耗 | 损失的太阳能 |
|---|---|---|
| rotation（之前） | 2,939,488 EU | 1,399,488 EU |
| merit（默认） | 2,006,480 EU（−32%） | 466,480 EU |
| economic | 1,340,000 EU（−54%，即理论最小值） | 0 |

三种模式下负荷都得到全部电力。

## 2. G4：负荷优先级

* 新公共 API `core.api.energy.grid.LoadPriority`（`CRITICAL` 重要 / `NORMAL` 普通 / `DEFERRABLE` 可延后）与 `ILoadPriority`。
* `AbstractEnergyBlockEntity`（SI 的机器与储能）实现该接口，并保存为 `load_priority`（普通时不写入）。
* 在能源管理终端的监控面板“设备”页点击设备的优先级即可切换。
* 分配：公平分配的四个阶段按优先级各执行一次，重要的先（字典序最大最小）。电力不足时先停可延后的负荷，最后才停重要负荷。
  * 储能的中继需求（为后方机器供电）使用该储能的优先级。
  * 全部为普通时，阶段与之前完全相同。
* 修改优先级是下一轮的输入，不改变拓扑。
* 用途示例：反应堆冷却剂注入器、区块加载器设为重要；物质生成机、充电器设为可延后。

## 3. G5：断路器与保险丝

新方块：

* **EU断路器导线**（`wiring/block_eu_breaker_cable`）：IV 导线，内置断路器。
  * 过载（反时限）：超过额定流量时热状态每 tick 增加 `(r² − 1) / (3 × 延时)`（r = 流量 / 额定），到 1 时断开。即 2 倍额定时经过设定延时断开，1.1 倍时约 14 倍延时，过载越大越快。低于额定时冷却。
  * 短路：10 倍额定流量当 tick 断开。
  * 过电压：数据包超过额定电压（可关闭）时立即断开。引擎在施加过电压效果之前检查：该次输送中，断路器后方的导线不会熔毁、绝缘不会烧毁、不会触电，机器不会爆炸。断路器前方照常。
  * 自动重合闸：3 秒后重新合上；连续第 4 次跳闸后闭锁，需在设置界面或监控面板中复位。可关闭自动重合闸。
  * 红石信号使其保持断开（与分流导线相同）。
  * 空手右击打开设置：额定流量（EU/t）、额定电压（关闭 / 32 / 128 / 512 / 2048 / 8192 / 32768）、延时（tick）、自动重合闸。默认 512 EU/t、无电压保护、20 tick、自动重合闸开。
  * 配方：分流导线 + 比较器 + 2 铁锭 + 红石。
* **EU保险丝导线**（`wiring/block_eu_fuse_cable`）：一次性保护，判定与断路器相同，熔断后保持断开，不受红石影响。用新的保险丝导线右击熔断的保险丝即可恢复（消耗一个）。熔断的保险丝不掉落。默认 128 EU/t、5 tick。配方：2 锡导线 + 红石 + 2 玻璃板 → 4 个。
* 时间配合：靠近机器的断路器延时短于干线断路器，故障时只有最近的断路器断开（离线测试：分支 300 EU/t 故障时分支断路器 4 tick 断开，干线保持闭合）。
* 实现：
  * 保护逻辑为纯计算类 `core.runtime.energy.engine.ProtectionRelay`。
  * 线缆为引擎的特殊导线（`IndependentSpecialCableBlockEntity` 增加保护继电器）。
  * 每次输送把电量计入路径上的每个断路器（原生 EU 与 FE 路径），每 tick 末尾评估。
  * 断开或合上与分流导线一样在下一个 tick 开始时发布，借助 G1 只重建该连通块。
* 原有的熔毁、爆炸效果保留为“没有保护时”的结果。

## 4. G7：电网监控面板

能源管理终端增加“面板”按钮，打开全屏监控面板（与原界面共用同一菜单，可随时切回）。分为 4 页：

* **概览**：
  * 发电、耗电、储能、收支；112 秒趋势图。
  * 按电源类别的供电（必须运行、燃料、储能放电）与当前调度模式。
  * 重要负荷的需求与缺口。
  * 本网络电源窗口的引擎耗时（µs/tick，含历史）。
  * 子网列表。
* **系统图**：单线图。每个子网一条母线，按导线额定分行；母线之间显示变压器（T）、储能（S）与断开的断路器（X）；母线下方显示该母线上的断路器状态。
* **设备**：全部设备（可按类别筛选），显示功率、额定、电压；用电器与储能可切换优先级；发电机显示调度类别；可远程开关。
* **保护**：
  * 断路器与保险丝：状态、流量与额定（含热状态）、设置、连续跳闸次数；断开的断路器可复位。
  * 警报记录：跳闸、重合、闭锁、复位、保险丝熔断、导线熔毁、绝缘烧毁、机器爆炸、重要负荷电力不足。
  * 警报只保存在内存中（每维度最近 128 条），按网络范围筛选。

终端的数据扩展：

* 遍历把断路器列为设备，断开的断路器像缓冲一样被跨越。
* 记录子网之间的连接与网络范围。
* 引擎按窗口的第一个电源累计耗时。
* 新数据包：`protection_settings`（断路器设置）与 `energy_terminal_action`（优先级、复位）。服务器重新检查：8 格内、设备属于该终端的网络、速率限制 `grid`。

## 7. 兼容与限制

* 次序与优先级只在 fair 分配模式中生效（legacy 模式不变）。它们在每个窗口（最多 32 个电源、128 个接收方）内生效；特别大的网络按窗口近似。
* 断路器的电压保护只作用于原生 EU 数据包；FE 路径只计入流量。
* 重要负荷的电力不足警报由终端检测（需要网络中有终端）。
* G6（导线载流量与发热）未实施。
