# 0.1.10.24 更新说明：发酵机的热量、全屏面板与 JEI / EMI、素材更新

基于 0.1.10.23。共 3 项：发酵机的热量计算与沼气产量与 IC2 不一致的报告、期货机全屏界面被 JEI 书签覆盖的报告、用户提供的新素材（3D 模型、纹理）与移除旧的「实验性风格」资源包。发酵机先在离线测试 `verify-si1124` 中把旧做法、IC2 的做法与新做法逐项比较，只修改与 IC2 不同的部分；未采用的部分与数值也写在下面。构建环境为 Gradle 8.10.2、JDK 21、NeoForge 21.1.218，离线构建。

## 1. 发酵机的热量（对齐 IC2 1.12.2）

### 参照

* 代码注释一直以 IC2 1.12.2 为参照。本机找到两份 IC2：`industrialcraft-2-2.8.222-ex112.jar`（1.12.2）与 `industrialcraft-2-2.2.828a-experimental.jar`（1.7.10，GTNH 服务端）。两份都复制到单独的文件夹，只用 `javap -c -p` 读取字节码与默认配置 `general.ini`，未运行。
* IC2 1.12.2 `TileEntityFermenter.work()`：
  1. 进度（已发酵的生物质）达到 `biomass_per_fertilizier`（500）时向肥料槽放入 1 个肥料，进度清零（槽满时肥料丢失）。
  2. 正面是热源，输入罐的流体有发酵配方，输入量 ≥ 一次运行的量，输出罐的空间 ≥ 一次运行的产量时，才向热源请求 100 HU（`drawHeat(side, 100, false)`），加入缓冲；缓冲 ≥ 配方热量时运行一次，缓冲减去配方热量（余量保留）。此时返回“工作中”（即使热源给了 0）。
  3. 其他情况不请求热量，返回“未工作”。
* 配方数值（`general.ini`）：1.12.2 为 20 mB 生物质 → 400 mB 沼气、4000 HU、每 500 mB 一个肥料，与本模组的配方 `fermenter/biomass_to_biogas` 相同。罐容量 10,000 / 2,000 mB 相同，没有热损耗相同。
* 界面：IC2 的“热量”条是本次运行的转换进度（缓冲 / 配方热量），另一条是肥料进度。

### 与 IC2 不同的部分（0.1.10.23）

* 储热 4000 HU 只要有空间就吸收热量，没有生物质、生物质不足一次运行或沼气罐已满时也会吸满；热源（固体、流体、电力、放射性同位素热能发生机都是推入热量）为此消耗燃料。机器内最多可存 4000 + 3999 HU。
* 热源推入与本机抽取各自最多 100 HU，同一 tick 合计可进入 200 HU（运行仍每 tick 最多取 100 HU）。
* 热量条显示储热（空转时显示满），不是本次运行的进度。
* 工作灯在有残留热量时常亮（热源拆除后也亮）。

### 离线比较

`verify-si1124/harness/Harness1124.java`：同一组条件下逐 tick 比较三种做法：OLD（0.1.10.23 的方块实体逻辑）、IC2（1.12.2 `work()`，IC2 热源每 tick 补满一 tick 的产量）、NEW（0.1.10.24，使用实际的 `FermenterHeatIntake` 类）。热源在正面，产热 10 / 50 / 100 / 200 HU/t；本模组的热源为推入方式（只送出机器接受的部分，其余留在热源，燃料消耗 = 机器接受的热量）。每格为 1 分钟（1,200 tick）。

| 情况 | 产热 | OLD | IC2 1.12.2 | NEW |
|---|---|---|---|---|
| 稳定运行（第 2 分钟）：运行次数 / 沼气 / 肥料 / 吸收热量 | 10 HU/t | 3 / 1,200 mB / 0 / 12,000 | 同左 | 同左 |
| | 50 HU/t | 15 / 6,000 mB / 1 / 60,000 | 同左 | 同左 |
| | 100 HU/t | 30 / 12,000 mB / 1 / 120,000 | 同左 | 同左 |
| | 200 HU/t | 30 / 12,000 mB / 1 / 120,000 | 同左 | 同左 |
| 没有生物质的 1 分钟：吸收热量 / 机器内存热 | 全部 | 4,000 / 4,000 | 0 / 0 | 0 / 0 |
| 沼气罐满（不取出）：第 1 分钟吸收热量 | 50～200 HU/t | 24,000（多 4,000，之后存热 4,000） | 20,000 | 20,000 |
| 生物质每 4 tick 1 mB：第 1 分钟运行次数 | 10 HU/t | 3（预先吸收的热量） | 2 | 2 |
| | 50～200 HU/t | 14，吸收 60,000 | 14，吸收 56,050～56,100 | 同 IC2 |

* 稳定运行的产量此前已与 IC2 一致；不一致的是空转与堵塞时的吸热、残留热量带来的提前运行、热量条与工作灯。
* 共 64 项检查全部通过：稳定、空转后、堵塞、缓慢供料各情况下 NEW 与 IC2 的运行次数、沼气、肥料、吸收热量相同；没有生物质时不吸热；每 tick 最多 100 HU；热量条每 tick 与 IC2 相同。

### 修改

* 新类 `common.recipe.fermenter.FermenterHeatIntake`（纯 Java，离线测试直接使用）：能开始一次运行的 tick 内最多接受 100 HU（推入与抽取合计），否则为 0。
* `mio_icif_fermenter_elc`：`receiveHeat` / `canReceiveHeat` 按上面的规则接受热量（热源看到“没有空间”时把热量留在自己那里，不消耗燃料）；“能否运行”按 IC2 判断（配方、一次运行的输入量、一次运行的输出空间），每 tick 计算一次，罐内容变化时重新计算；本机抽取移到单元槽与肥料之后（与 IC2 的顺序相同）。
* 热量条（菜单数据 3 / 4）改为本次运行已获得的热量 / 配方热量（IC2 的转换进度）。
* 工作灯：能运行且最近一 tick 有热量进入或投入运行时点亮；残留热量不再使其常亮。
* 指南“发酵机”页（英、中、日）加一条说明。
* 旧存档里已存的热量照常用于运行（每 tick 最多 100 HU），不会丢失。

### 未采用的部分

* IC2 1.7.10（2.2.828a）的默认值：10 mB → 200 mB、8000 HU（每 HU 的沼气是 1.12.2 的 1/4；100 HU/t 时每分钟 3,000 mB，1.12.2 为 12,000 mB），运行时缓冲直接清零（本 tick 多取的热量丢失：30 HU/t 时每次运行丢 10 HU）。本模组按 1.12.2，未采用。需要 1.7.10 的平衡可以用数据包修改配方 `fermenter/biomass_to_biogas` 的数值（清零规则不能改）。
* IC2 只要正面有热源方块且能运行就显示“工作中”，热源没有燃料时也亮；未采用（本模组以实际有热量为准）。持续供热时两者亮灯的 tick 相同（1,200 / 1,200）。
* 热源方块实体在发酵机之后更新时，热量晚一 tick 进入：第 1 分钟比 IC2 少 1 次运行（10 HU/t：2 对 3，100 HU/t：29 对 30），第 2 分钟起相同。旧做法也是如此；要消除需要把本模组的推入式热源改为 IC2 的抽取方式，未修改。

## 2. 全屏面板与 JEI / EMI

* 原因：期货机界面在构造时 `width` 还是 0，`imageWidth` 设为 0；`super.init()` 按这个宽度把面板居中，`leftPos` 成为屏幕宽度的一半；之后虽然把 `imageWidth` 改为屏幕宽度，`leftPos` 没有恢复。JEI 把面板左边的半个屏幕当作空闲区域，在那里显示书签并接收点击。电网监控面板（0.1.10.22）已经把 `leftPos` / `topPos` 设为 0，全屏面板只有这两个。
* 修改：期货机界面在 `init()` 中把 `leftPos` / `topPos` 设为 0。`JEIPlugin` 为两个面板注册 `IGuiContainerHandler`（GUI 额外区域 = 整个窗口），JEI 不在面板上显示配料列表与书签。`MioIcifEmiPlugin` 注册排除区域：两个面板为整个窗口；机器界面左侧的工具栏（升级槽、按钮）与 JEI 的处理相同（此前 EMI 没有排除区域）。
* 需要在游戏中确认（JEI、EMI 各自）：面板上不再出现书签 / 收藏栏，点击到达面板。

* Minecraft 1.21.1 只加载 0 / ±22.5 / ±45 度、单轴的元素旋转（`BlockElement.getAngle`），其他角度会使整个模型无法加载（显示缺失模型）。65 处旋转改为同一轴上最近的允许角度，双轴旋转保留较大的一轴（与 0.1.10.11 相同的处理）。其余内容（元素、UV、显示变换）保持原样。修改后 389 个带元素的模型全部满足加载规则。
* 等离子加农炮与战术镭射步枪缺少 `particle` 纹理，补为同一纹理。
* 对应关系：没有 `item_tool_plasma_cannon` 与 `item_tool_advanced_laser_rifle` 这两个物品。进阶镭射步枪对应唯一的进阶步枪 `item_tool_advanced_electric_rifle`。`item_tool_plasma_launcher（等离子发射器）` 按 ID 对应等离子发射器（新模型保留了现有模型的铜环、紫色腔体与叉形发射口），剩下的等离子加农炮对应电力等离子电浆发射器 `item_tool_electric_plasma_gun`。等离子加农炮文件的 `credit` 写着由 `tools/art/plasma_launcher_1104.py` 生成；若两者应当对调，只需修改 `work-1124/tools/models_1124.py` 的对应表一行。
* 等离子发射器原来的 3D 纹理是 6 帧动画（128×768），新纹理为一帧，删除了旧的 `.mcmeta`。这 11 个物品的 2D 图标（`textures/item/*.png`）不在素材包中，保持不变。

### 纹理（textures.zip）

* 1,296 个文件全部对应到 `assets/mio_icif/textures` 下的同一路径：1,251 个与现有文件相同，43 张图像与 1 个动画文件（中子板）被替换，新增 1 个动画文件（量子核心：16×16 → 16×96，6 帧）。没有找不到对应位置的文件。尺寸变化：中子板 16×288（18 帧）→ 16×32（2 帧，随附新的动画文件）、量子核心。

### 移除「实验性风格」资源包

* 删除内置资源包 `resourcepacks/si_experimental`（680 个文件：精致机器模型与纹理、DSP 风格物品图标、状态灯列表）、注册它的 `common.client.AppearanceStyle`、生成它的 `tools/build_appearance_packs.py`。模组 jar 中不再有 `resourcepacks/`。
* 装备控制台“外观”页：第一页（原“纹理”）的“默认 / 实验性”风格卡片与重新加载说明删除，护手覆盖（第一人称、第三人称）与框架核心外装两个开关上移，页名改为“装甲”；第二页“配色”不变。删除 12 个语言键（×4 种语言，含 `pack.mio_icif.experimental`），新增 `...appearance.page.suit`，标签提示改为“外观设置：装甲显示与配色”（`tools/lang_1124.py`，`--check`）。
* 状态灯的模型与 `StatusLampModels` 保留：基础资源中的状态灯列表为空（与之前的默认风格相同，不显示状态灯），其他资源包仍可提供列表。

* 开发用截图工具 `CaptureDirector` 中切换风格的步骤删除。
