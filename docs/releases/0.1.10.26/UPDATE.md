# 0.1.10.26 更新说明：交易所 X3——系统悬赏三个等级、国库与宝库循环、每周上限的发行、si_exchange 数据包、Java API 与事件

基于 0.1.10.25。交易所设计方案（Q1～Q8 按推荐批准）按 X1 → X3 → X2 → X4 的顺序实施，本版为 X3。新规则先在离线测试 `verify-si1126`（`Harness1126`）中与 0.1.10.25 的“市场委托”在相同的场景下比较（一年的发布、全部当天交付、2～4 名玩家合作、单人与多人、到期、存档），只采用确认有改进的部分。与方案不同的地方见第 9 节。

## 1. 三个等级的系统悬赏（`BountyBoard`）

0.1.10.21～0.1.10.25 的“市场委托”（`postSystemCommissions`：每天 3 件，市场缺少的商品 32～128 个，奖励为卖价的 1.15 倍，全部用新发行的货币支付，3 天）不再发布；存档中已有的继续留在委托板上直到到期。配置 `systemCommissionsPerDay` 已删除。

| 等级 | 来源 | 发布 | 期限 | 奖励 |
|---|---|---|---|---|
| 普通 | 市场缺少的商品自动生成（无解锁进度、国库少于 64 个），或 tier 为 normal 的数据包表（默认：钻石 6、绿宝石 8、金锭 12） | 每天保持 3～5 件（每天固定） | 3 天 | 价值 × 1.15，奖励池 `mio_icif:normal`：货币，或国库中的电路、橡胶、合金锭、青铜锭、碳板 |
| 高级 | 数据包表（默认 7 组：电子、合金、高级电子、金属、食物、木材、铱） | 每个交易周 2～3 件，分散在一周内 | 7 天 | 价值 × 1.3，奖励池 `mio_icif:advanced`：货币、国库的中间材料、制作的升级与机器外壳、UU 物质 1 桶 |
| 特别 | 数据包表（默认：龙首、鞘翅、下界之星、海洋之心；需要在线玩家完成相应进度） | 每天 5% 的概率，同时最多 1 件 | 7 天 | 奖励池 `mio_icif:special`：制作的混合 / 终极混合太阳能板（每周 1 个），宝库中的稀有物品，UU 物质 2 桶；没有货币 |

- **价值**：要求的物品按发布时市场的卖价（价格 × 1.03）计价；不是商品的物品用表中的 `value`。自动生成的普通委托价值 = 4,000 × 0.5～1.5，数量 = 价值 ÷ 卖价（四舍五入），须在 16～256 个之内。
- **奖励来源**（方案 C3）：
  - 国库：市场之前收购的库存，发布时预留，不产生新物品。
  - 宝库：交付给悬赏的稀有物品（不是商品的物品）进入宝库，之后作为特别悬赏的奖励发出，稀有物品在经济中循环。
  - 发行：制作的物品与 UU 物质，在发布时计入该等级的每周上限（高级 16 个、特别 1 个、UU 物质合计 4,000 mB）。
  - 货币：支付时发行。
  - 无法支付的条目不会被抽中；全部无法支付时普通与高级悬赏改为货币（价值 × 倍率），特别悬赏不发布。奖励永远不会是该悬赏自己要求的物品。
- **市场不出售**：普通或高级悬赏仍需要某商品时，市场不出售该商品（奖励高于卖价，否则“从市场买来交付”每件普通悬赏可得 566 货币）。
- **交付**：期货机面板新增第 7 页“悬赏”，按“交付”交出物品栏主区域中该悬赏仍需要的普通物品。`first`（默认）：每次交付按交付价值的比例立即支付各项奖励；`contribution`：完成或到期时按每名玩家交付的价值分配（最大余数法）。
- **多人的公平**：高级悬赏在最后一天之前一名玩家最多交付价值的 50%（可越过最后一个物品；见第 9 节）。单人游戏中所有悬赏都可以一人完成（系统悬赏没有“不能交付自己的委托”的限制）。
- **到期**：未支付的预留奖励退回国库与宝库；未支付的制作物品与货币不会产生；按贡献分配的悬赏按已交付的比例支付。
- **每周**：交易周 = 7 个交易日（`BountyMath.week`）。高级悬赏的数量与发行余量按周重置。

## 2. 离线比较（`Harness1126`，一年 364 天，所有悬赏当天交付，国库每天减半）

| | 件数 | 价值 p10 / 中位数 / p90 / 最大 | 每周发行的货币（平均 / 最大） | 单件最大货币奖励 |
|---|---|---|---|---|
| OLD 0.1.10.25 市场委托 | 1,092 | 989 / 4,120 / 79,104 / 1,054,720 | 708,416 / 2,261,941 | 1,212,928 |
| NEW 0.1.10.26 悬赏 | 1,570 | 2,496 / 4,429 / 5,940 / 34,944 | 146,761 / 195,980 | 45,427 |

- 典型委托的价值几乎不变（中位数 4,120 → 4,429），但旧规则按“16 的倍数 × 价格”决定数量，昂贵商品（附魔金苹果 128 个：1,212,928 货币）一件就发行巨额货币。价值的离散度（p90 / p10）由 80 倍降为 2.4 倍，每周发行的货币减少约 79%。
- 发布：普通 1,430 件、高级 124 件、特别 16 件。用国库物资支付的奖励价值 160,079（不产生新物品）。
- 每周上限：高级每周最多制作 10 个（上限 16），特别最多 1 个（上限 1），UU 物质每周最多 3,000 mB（上限 4,000）；计数器在全年内从未超过上限。
- 宝库循环（特别悬赏概率 100% 的测试）：交付的稀有物品 101 个 = 宝库中 43 + 已作为奖励发出 58 + 预留 0。
- 2～4 名玩家合作（各 2,000 次）：奖励份额与交付价值份额的平均偏差 `first` 0.083～0.105，`contribution` 0.049～0.059；一个不可分的制作物品在 `first` 下总是给最后交付者，在 `contribution` 下 99.8% 给最大贡献者。
- 多人份额：一人在第 0 天交付 51.4%（越过一个物品），两人在第 0 天完成；第 5 天仍受限，最后一天可完成剩余部分；单人一次完成。
- 价值取整：委托数量平均误差 0.4%、最大 3.1%；奖励物品在半个物品之内（10 个以上最大 5.2%）。
- 到期（5,000 次随机部分交付）：国库与宝库物品“到期后库存 + 已支付 = 发布前库存”；制作的物品不会重复支付。
- 同一世界种子发布相同的悬赏（种子 = 主世界种子）。

## 3. si_exchange 数据包

```
data/<命名空间>/si_exchange/
  bounties/*.json      悬赏表
  rewards/*.json       奖励池
  listings/*.json      开服即上市的玩家上市品
  economy.json         经济设置的默认值
  commodities/*.json   市场商品（si_futures 格式，在所有 si_futures 之后读取）
```

- 格式、默认内容与示例见 `docs/datapacks/si_exchange.md`。`/reload` 时检查，错误写入日志并可用 `/mio_icif bounty errors` 查看。
- **经济设置的优先顺序**（方案 D1）：服务器配置中修改过的值（与默认值不同）＞ 数据包 `economy.json` ＞ 模组默认值（`EconomySettings`）。键名与配置 `FutureMarket` 分区相同（X1 的卖出深度、额度、手续费、进口等，以及所有 `bounty*` 键），另有只能在数据包中设置的 `bountyNormalPool` / `bountyAdvancedPool` / `bountySpecialPool`。
- **初始上市品**：`listings/*.json` 的物品开服或 `/reload` 后直接成为玩家上市品（无需委托证据，单人游戏中也可用），不会因长期无成交而下市（存档标记 `Datapack`）。
- **商品的新字段**（`si_futures` 与 `si_exchange/commodities`）：`tag`（出售箱与集中清算也收购该物品标签中的物品，按本商品出售）、`accept_components`（也收购带有改动组件的物品）。两者同步到客户端，出售箱的格子与服务器一致。挂单仍只接受商品物品本身。

## 5. Java API 与事件（`core.api.exchange`，API 指南第 22 节）

- `ExchangeApi`：`commodities`、`quoteSell`、`quoteBuy`、`treasury`、`vault`、`ledger`、`mailboxCoins`、`deposit` / `withdraw`（带原因代码，账本记录发行 / 销毁）、`bounties`、`postBounty(表 ID)`、`postBounty(BountySpec)`、`cancelBounty`。只在服务器线程调用。
- 数据类型：`BountyTier`、`BountySplit`、`BountyNeed`、`BountyReward`（`Kind` / `Source`）、`BountySpec`、`BountyInfo`、`ExchangeApi.Commodity` / `Quote` / `LedgerDay`。
- 事件（`NeoForge.EVENT_BUS`）：`BountyPostingEvent`（可修改要求、奖励、天数与分配方式，可取消）、`BountyCompletedEvent`、`ExchangeTradeEvent`（成交后，在操作完成后发布，不在库存操作中途）、`MarketDayEvent`。KubeJS 与 FTB Quests 可以通过这些事件联动，奇点迭代不依赖它们。
- 账本（`LedgerDay`）新增：悬赏发行的货币、悬赏制作的物品与 UU 物质、API 按原因代码的存取。

## 9. 与方案的差异、未采用的部分

- **每名玩家份额可越过最后一个物品**：方案为“一人最多 50%”。离线测试发现，按整个物品取整时，两名玩家各自停在 50% 以下，剩余 114 货币的价值谁都不能交付，要等到最后一天。现在玩家在未达份额时可以交付越过份额的那一个物品（一人最多 51.4%），两人在第一天即可完成。
- **制作的奖励在发布时计入每周上限，到期也不退还**：保守的做法，保证上限对实际发行有效。特别悬赏到期时本周的预算会被用掉。
- **价格高于约 375 的 11 种商品不会出现在自动生成的普通委托中**（16 个以上就超出价值范围）：附魔金苹果、金苹果、电路、高级电路、合金锭、铱、金锭、钻石、绿宝石、远古残骸、下界合金锭。其中电路、合金、铱、高级电路、金锭出现在高级悬赏，钻石、绿宝石、金锭另有默认的普通悬赏表。
- **奖励中的 UU 物质为固定数量**：没有按价值换算（方案 §1.6(b) 的 UU 校准仍未确定）。
- **方案中商品的 `tag` 只用于出售箱与集中清算**：挂单（订单簿）与悬赏交付仍只接受物品本身。
- **未采用**：特别悬赏默认按贡献分配（默认 `first`，表可指定 `contribution`）；悬赏要求中的物品标签。
- **不在 X3 范围**（按计划在 X2 / X4）：交易终端、结算槽（潜影盒、背包、AE2 存储元件）、硬币⇄UU 的板、ID 卡、自动稳定、回收。
