# 0.1.10.27 更新说明：交易所 X2——交易终端与大宗结算槽

基于 0.1.10.26。交易所设计方案（Q1～Q8 按推荐批准）按 X1 → X3 → X2 → X4 的顺序实施，本版为 X2（方案 §4 B1～B5，Q3：所有者离线时只运行每日集中清算，Q4：AE2 只以“元件放入槽位”的方式联动，不连接 ME 网络）。自动交易的规则先在离线测试 `verify-si1127`（`Harness1127`）中与手动交易比较，只采用确认没有额外好处、也没有额外损失的做法。与方案不同的地方见第 8 节。

## 1. 交易终端（新方块 `producer/block_trade_terminal`）

交易终端在其区块加载期间，为放置它的玩家（所有者，`MachineActionOwner`）在交易所自动交易。

- **所有者与权限**（`TerminalRules`）：等级 查看 1 ＜ 交易 2 ＜ 设置 3 ＜ 所有者 4。所有者可以把最多 16 名玩家加入权限列表（查看 / 交易 / 设置），也可以给所有者计分板队伍的成员设定一个等级；管理员（权限 2）视为“设置”。列表与队伍取较高者，列表最高只能给“设置”。只有所有者能编辑权限。

| 操作 | 需要 |
|---|---|
| 打开、查看 | 查看 |
| 向出售缓冲区放入物品、使用结算槽（以自己的身份） | 交易 |
| 编辑订单、输出模式、从缓冲区取出、把输出缓冲区卸入结算容器、立即运行 | 设置 |
| 编辑权限列表与队伍等级 | 所有者 |

- **出售缓冲区**（27 格）：管道和漏斗放入商品（也包括商品 `tag` 中的物品、`accept_components` 允许的物品）；管道不能从中取出。交易等级的玩家可以手动放入；Shift 点击只对能取回的玩家（设置）放入出售缓冲区，避免误交给所有者。
- **输出缓冲区**（9 格）：输出模式开启时购买的物品放入这里，管道可以取出；关闭时购买的物品进入所有者的邮箱。
- **常设订单**（最多 8 个，每 200 tick 运行一次，按方块坐标错开）：
  - 卖出：保留 N 个，其余交给每日集中清算（最低平均价为无卖压时买价的百分比），或立即出售（每件最低价格）。
  - 买入：补到目标库存 N（库存 = 输出模式下的输出缓冲区，否则为所有者邮箱中的该物品），每件最高价格，用所有者邮箱中的货币支付（先按上限冻结，余额退回邮箱）。
  - 立即出售与买入凑满 64 件再成交（买入：目标小于 64 时为整个目标；出售：缓冲区没有空格时也成交）；集中清算不需要（见第 3 节）。
  - 所有者离线时只运行集中清算的卖出订单，需要解锁进度的商品等待所有者上线（Q3）。所有者在线但尚未解锁的商品显示“未解锁”。
  - 每个成交的订单消耗一次交易的能量（与期货机相同的配置项）。
- **结算**：所有交易都属于所有者的 UUID，与手动交易使用同一组函数：立即出售 = `ExchangeService.sellForAccount`（先与不低于市场买价的玩家买单成交，再按卖出深度、价值上限、账本、卖压卖给市场，最后与其余买单成交到限价），集中清算 = 并入所有者当天该商品的唯一清算订单（`addAuction`），买入 = `buyForAccount`（盘口、国库与进口、所有者的每日买入上限、账本）。出售所得进入所有者的邮箱。
- **交易日**：期货机的换日逻辑原样移到 `MarketDayDriver`，期货机与交易终端都会推进交易日；只有交易终端的基地也会进行每日集中清算。换日使用主世界的时间（之前为机器所在维度的时间；原版维度相同）。
- **拆除**：缓冲区中的普通物品进入所有者的邮箱，带改动组件的物品掉落在原地。
- **界面**（5 页）：缓冲区（缓冲区、结算槽、输出模式、立即运行、所有者邮箱的货币、能量）、常设订单（列表、状态与原因、编辑器）、权限、记录（最近 32 笔成交）、大宗结算（见第 2 节）。
- 能量：LV，最大输入 100 EU/t，储能 10,000 EU（期货机的配置项）。配方：基础电路 ×4、绿宝石、漏斗 ×2、期货交易机、箱子。

## 2. 大宗结算槽（期货机面板第 8 页“大宗结算”与交易终端第 5 页）

在槽位中放入容器，以自己的身份批量操作（`Settlement`、`SettlementStorage`）：

| 容器 | 读取方式 |
|---|---|
| 潜影盒、其他模组的背包 | 物品处理器能力 `Capabilities.ItemHandler.ITEM`（NeoForge 为潜影盒提供） |
| AE2 物品存储元件 | `StorageCells.getCellInventory`（AE2 已加载时） |
| AE2 流体存储元件中的 UU 物质 | 同上，`AEFluidKey`（mB） |
| 装有 UU 物质的流体容器 | 流体处理器 |

- **报价**：每种商品的数量、立即出售与集中清算的所得（与出售箱相同的计算），不能出售的物品数，UU 物质，可以交付的悬赏与委托。
- **出售**：立即出售（卖出深度、价值上限）或交给集中清算。物品先从容器取出再出售，市场没有收购的部分放回容器（放不下时进入背包、邮箱），不会产生或丢失物品。
- **交付**：容器中的普通物品交付给系统悬赏或玩家委托（悬赏与委托的规则不变，物品来源由背包改为容器：`ItemSource`）。
- **UU 物质存入账户**。
- **购买放入容器**：按价格上限与数量立即买入（与手动买入相同，用身上的货币支付），物品放入容器，放不下的进入背包、邮箱。
- 交易终端另有：把容器中的商品装入出售缓冲区（交易），把输出缓冲区卸入容器（设置）。
- 槽位属于每名玩家自己的界面，关闭界面时容器退回（背包已满时掉落）。所有结算操作消耗一次交易的能量；装入、卸出不消耗。
- **AE2 为可选联动**：AE2 相关代码只在 `common.integration.ae2.Ae2SettlementCells`，仅在 AE2 已加载时通过反射创建；未安装 AE2 时其余容器照常工作，AE2 的任何错误只会使该次操作不可用。

## 3. 离线比较（`Harness1127`，纯 Java，39 项检查全部通过）

默认参数：价差 6%，个人深度 256，服务器深度 1,024，价值上限每天 50,000。

- **自动 = 手动**：同一天把 N 个商品分批卖出（每次运行一批）与一次手动卖出相比，终端从不多得，差额只来自每次出售向下取整（每次少于 1 货币）。批量 64 时最多少 0.7%；在价值上限内、或已有 500 个卖压时同样成立。
- **按所有者计算**（未采用的做法：按终端计算）：3,000 个价格 200 的商品，按所有者计算时任意台数都得到 39,716（一次手动出售 39,731）；若按终端各自计算深度，2 / 4 / 8 台分别多得 66.4% / 148.4% / 226.3%。因此所有自动交易计入所有者的 UUID。
- **集中清算并入一个订单**：终端 25 次提交（每次 80 个）并入所有者的一个订单，所得与一次手动提交 2,000 个完全相同（35,159）；若作为 25 个独立订单清算则多得 203.1%（106,550）。
- **凑批（新规则）**：管道每次运行只送来 1 个时，每次立即出售 1 个的取整损失：

| 价格 | 一次出售 3,000 个 | 每次 1 个 | 每批 64 个 | 损失（每次 1 个 → 每批 64 个） |
|---|---|---|---|---|
| 8 | 1,589 | 1,193 | 1,578 | 24.9% → 0.7% |
| 40 | 7,946 | 7,381 | 7,934 | 7.1% → 0.2% |
| 200 | 39,731 | 39,006 | 39,716 | 1.8% → 0.0% |
| 1,000 | 198,655 | 197,747 | 198,635 | 0.5% → 0.0% |

  买入每次向上取整：价格 8 时每次买 1 个多付 9.22%，每批 64 个多付 0.12%（价格 40：1.94% → 0.01%）。因此立即出售与买入凑满 64 件再成交。
- **离线规则**：集中清算的卖出订单在所有者在线与离线时都运行；立即出售与买入只在在线时运行；需要解锁的商品离线时等待；关闭的订单、没有超出保留数量时不交易。
- **买入计划**（10 万个随机情况）：买入量 = min(目标 − 库存, 邮箱货币 ÷ 上限)，从不为负、不超过目标、不超过货币；状态为“已成交”当且仅当会买入；上限 0 不买。
- **权限矩阵**：所有者、管理员、列表（查看 / 交易 / 设置）、队伍成员、陌生人 × 9 种操作全部符合上表；列表中写成“所有者”的条目只得到“设置”。
- **错开运行**：每台终端每 200 tick 恰好运行一次；10 × 10 排列的 100 台在同一 tick 最多 5 台（不错开时 100 台同时运行），竖直一列 100 台每 tick 最多 1 台。

## 5. 代码结构

- `MarketDayDriver`：换日（初始化、记录价格、滚动历史、事件、改价、交易所换日），由期货机的 `checkDayUpdate` 原样移出。
- `ExchangeService`：`place` 的三段撮合移到 `execute`（买入的市场部分为 `marketBuy`），规则不变；新增 `sellForAccount`、`buyForAccount`、`addAuction(UUID, 名称, …)`、`sellableAs`（不检查解锁，用于出售缓冲区）、`mailStack`、`team(server, 名称)`；`place` 与 `deliver` 新增带结算容器的重载，`Bounties.deliver` 新增带物品来源的重载。
- 新类：`TerminalRules`（纯 Java）、`TerminalOrders`、`TerminalPackets`、`TerminalView`、`TerminalClientState`、`Settlement`、`SettlementStorage`、`SettlementStorages`、`ItemSource`、`Ae2SettlementCells`、`TradeTerminalBlockEntity`、`TradeTerminalMenu`、`TradeTerminalScreen`、`mio_icif_block_trade_terminal`。
- 通信：交易所动作 15～19（结算槽），终端的请求 / 动作 / 视图三个新数据包。`ExchangeView` 末尾追加结算视图。公共 API 未改变。

## 8. 与方案的差异、未采用的部分

- **凑批 64 件**（方案中没有）：见第 3 节，每次运行只成交 1 件时便宜商品会因取整损失最多约四分之一的价值。
- **按所有者的 UUID 计算、集中清算并入一个订单**：方案已有的原则，离线测试给出不这样做时的多得比例（第 3 节）。
- **需要解锁进度的商品在所有者离线时不交易**（包括集中清算）：离线时无法读取所有者的进度。
- **结算槽属于每名玩家的界面**，不保存在方块中；容器在关闭界面时退回。
- **只有物品处理器能力的容器**：没有该能力、只带原版 `container` 组件的物品（例如用中键复制的箱子）不接受。潜影盒由 NeoForge 提供该能力。
- **未采用**：终端连接 ME 网络或从相邻容器直接抽取（Q4）；管道从出售缓冲区取出；离线时的立即出售与买入（Q3）。
- **不在 X2 范围**（按计划在 X4）：硬币 ⇄ UU 的盘口、ID 卡、自动稳定、回收。
