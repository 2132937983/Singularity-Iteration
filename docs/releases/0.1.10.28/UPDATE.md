# 0.1.10.28 更新说明：交易所 X4——货币与 UU 物质交易板、ID 卡、废料回收、自动稳定器（交易所改版完结）

基于 0.1.10.27。交易所设计方案（Q1～Q8 按推荐批准）按 X1 → X3 → X2 → X4 的顺序实施，本版为最后的 X4（方案 §A5、§B4、§B6 / Q7、§D4）。四项规则先作为纯 Java 类在离线测试 `verify-si1128`（`Harness1128`）中测量，只采用确认不产生新的货币来源、也不给玩家带来额外损失的做法。与方案不同的地方见第 7 节。

## 1. 货币与 UU 物质交易板（`UuBoard`，方案 §B6 / Q7）

- 新市场 `mio_icif:uu`，在面板中显示为“UU 物质（每份 100 mB）”（图标为 UU 物质桶）。交易单位为 UU 账户中的 **100 mB 一份**，价格为每份的货币。
- 只在玩家之间交易：使用普通的订单簿（价格时间优先、同一玩家或队伍不成交、挂单 7 天、卖方手续费 1% 销毁）。**市场本身从不买卖 UU 物质**——市场若用货币收购 UU 物质，“EU → UU → 货币”就会成为无上限的发行来源。
- 卖单冻结 UU 账户中的份数（不足时拒绝），买单冻结身上的货币；成交时 UU 物质进入买方账户，货币（扣除手续费）进入卖方；撤回或到期时冻结的 UU 物质退回账户。
- 价格范围 1～10,000,000 货币 / 份；参考价按校准的“每桶货币”换算（每 100 mB）。配置 `uuBoard`（默认开）。
- 离线（20 名玩家、50,000 个随机订单）：32,148 笔成交、422,463 份；货币“期末持有 + 销毁的手续费 = 期初持有”（10,265,473 = 8,133,013 + 2,132,460），UU 物质精确守恒（1,698,500 mB），任何账户都不为负。

## 2. ID 卡（`IdCardRules`、`IdCards`，方案 §B4）

- 新物品 **ID 卡**（`normal/item_id_card`，配方：纸 ×2、金粒、基础电路 → 2 张）。数据组件 `mio_icif:id_card`：发行者与持有人（UUID 与名称）、权限、到期日、编号、种类、签名。
- **签名**：服务器以世界的密钥（`ExchangeData.Cards.Secret`，首次使用时用 `SecureRandom` 生成）对全部字段做 SHA-256。改动任何字段（权限、期限、持有人、发行者、编号、种类）或在其他世界签发的卡都无法通过验证。
- **生物认证**：卡只对持有人本人有效；被盗或转交的卡对他人没有任何作用。
- **个人卡**：使用空白卡即成为自己的个人卡。在任何地方使用都会打开“交易所账户”画面：邮箱（货币、UU、物品）、今日剩余额度、稳定器状态、挂单与拍卖订单（可撤回；远程撤回的退款一律进入邮箱，不会远程把物品放进背包）、自己发出的委任卡（可逐张或全部吊销）。
- **委任卡**：交易终端所有者在新的“ID 卡”页为某位玩家写入一张空白卡：权限为查看 / 交易 / 设置（最高为设置，不能给所有者权限），期限 1～30 个交易日。持有人在该所有者的**所有**交易终端获得此权限，直到到期或被吊销（所有者的登记表中删除）。每名发行者最多同时 16 张；到期的卡在换日时从登记表中删除。
- 离线：10,000 张随机卡全部对持有人有效；改动任一字段或换用其他密钥全部失效；盗用者 NOT_HOLDER；最后一天有效、次日 EXPIRED；吊销后 REVOKED；只在发行者的终端生效。

## 3. 废料回收（`ScrapRules`、`ScrapSink`，方案 §A5）

- 立即出售（出售箱、大宗结算、交易终端的新模式“其余回收”）可选择 **“其余回收为废料”**：出售照常进行（每件出价至少 1 货币、在每日额度内），**所得货币与不选时完全相同**；剩下的物品若市场几乎不再收购——下一件的出价低于下限 `max(1 货币, scrapThreshold × 无卖压出价)`（默认 5%）——就改为回收：按 SI 回收机的比率（有回收机配方的物品得到配方产物与几率，否则为废料，IC2 的 1/8），以期望值支付（8 件得 1 个废料，不足 8 件的余数留给卖家）。
- 回收的物品被销毁，不进入国库、不计入卖压；账本记录“回收收入 / 废料产出”。被每日额度挡住而出价仍高于下限时不回收（这些物品明天还能换到货币）。
- 离线（一名玩家一天卖出 640 / 3,000 / 10,000 件，价格 8 / 40 / 200 / 1,000）：12 种情况下货币与不选时完全相同，废料 = 剩余件数 ÷ 8，留下的余数不足 8 件；共产出 5,609 个废料。

## 4. 自动稳定器（`Stabilizer`，方案 §D4）

- 每次换日，比较最近 7 个已结束交易日的**净发行**（发行 − 销毁）与目标：目标 = max(**每名活跃卖家每周 `stabilizerTargetPerPlayerWeek`（100,000）**, 货币总量估计 × `stabilizerTargetPercentPerWeek`（2%）)。活跃卖家 = 这 7 天内向市场出售过的玩家；货币总量估计 = 账本开始以来的累计净发行。
- 超过目标时系数下降一步（`stabilizerStep` 5%，最低 `stabilizerMinFactor` 0.5）；低于目标的 80% 时恢复一步；两者之间保持。系数同时作用于**所有商品的卖出深度**与**每日额度**，因此大量出售与自动化出售的货币减少，而少量出售几乎保持原价（系数 0.5 时：64 件保留 86.6%，3,000 件保留 50.0%）。
- 默认**关闭**（`stabilizerEnabled`）。“国库”页显示状态（系数、7 天净发行 / 目标、货币总量估计、活跃卖家、7 天的废料回收）；个人卡画面也显示系数。
- 离线一年（364 天；购买销毁前一天收入的 35%，悬赏每天发行 21,000）：

| 服务器 | 稳定器 | 每周净发行 | 最后 8 周每名卖家 | 系数（期末 / 最低 / 平均） | 普通卖家所得 | 大量卖家所得 |
|---|---|---|---|---|---|---|
| 普通（1 名大量卖家 1,500 件 / 天，6 名普通卖家 16～64 件 / 天） | 关 | 475,040 | 67,084 | 1 / 1 / 1 | 17,250,856 | 8,957,194 |
| 普通 | 开 | 475,040 | 67,084 | 1 / 1 / 1（不动作） | 相同 | 相同 |
| 自动化（4 名玩家每天 4 种商品各 1,000 件，4 名普通卖家） | 关 | 922,835 | 117,149 | 1 / 1 / 1 | 6,956,012 | 55,026,786 |
| 自动化 | 开 | 734,428 | 91,304 | 0.704 / 0.626 / 0.737 | 6,488,107（93.3%） | 40,443,853（73.5%） |

  一年中系数改变方向 12 次（每天最多一步，无振荡）。

## 6. 配置与存档

| 键（`FutureMarket`） | 默认 | 说明 |
|---|---|---|
| `uuBoard` | true | 货币与 UU 物质交易板 |
| `scrapThreshold` | 0.05 | 废料回收的下限（无卖压出价的比例；0 = 不回收） |
| `stabilizerEnabled` | false | 自动稳定器 |
| `stabilizerTargetPerPlayerWeek` | 100,000 | 目标：每名活跃卖家每周的净发行 |
| `stabilizerTargetPercentPerWeek` | 2.0 | 目标：每周货币总量估计的百分比（取较大者） |
| `stabilizerStep` | 0.05 | 每个交易日的步长 |
| `stabilizerMinFactor` | 0.5 | 最低系数 |

- 以上各键也可在数据包 `economy.json` 中设置（优先顺序同 0.1.10.26）。
- 存档 `mio_icif_exchange` 新增：`Stabilizer`（系数、货币总量估计、已计入的日）、`LastSale`（每名玩家最后出售的日）、`Cards`（密钥、编号、各发行者的委任卡登记）、账本的 `ScrapIn` / `ScrapOut`。物品组件 `mio_icif:id_card`。

## 7. 与方案的差异、未采用的部分

- **废料回收不减少货币**：方案为“价格低于 5% 的部分以废料代替货币”。离线发现，若出售只付到下限（5%）为止，卖家先不选回收卖一次、再选回收卖一次即可同时得到全部货币与废料（价格 1,000、10,000 件：198,451 货币 + 1,073 废料，而单次为 188,648 + 1,173），下限形同虚设。现在出售的货币与不选回收时完全相同，回收只接收出售剩下、且出价低于下限的物品。
- **稳定器的目标按活跃卖家计算**：方案为“货币总量的 +2%/周”。货币总量估计从 0 开始，只用比例时新服务器的全部早期发行都算作通胀：普通服务器一年中系数平均 0.508（几乎全年处于最低）。现在目标取“每名活跃卖家 100,000 / 周”与“总量的 2%”中的较大者，普通服务器不动作。
- **稳定器同时缩小每日额度**：只缩小深度时，分散出售多种商品的玩家几乎不受影响（每日额度先起作用）。
- **恢复阈值为目标的 80%**：最初的 50% 会让净发行在目标附近波动的服务器只降不升。
- **稳定器默认关闭**：方案中为“任意”；离线结果见第 4 节，是否默认开启请服务器或整合包决定。
- **ID 卡的远程操作只限查看与撤回**：远程撤回的退款进入邮箱，远程不能下新单或领取邮箱（仍需期货机）。委任卡只用于交易终端的权限。
- **未采用**：系统作为 UU 物质的交易对手（Q7）；委任卡让持有人查看发行者的账户（隐私）。
