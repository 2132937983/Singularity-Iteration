# 0.1.10.29 更新说明：游戏内测试的五项反馈——蓝波顿配方、方块切割机的木材、交易面板的数字输入、货币账户、最低价批量出售

基于 0.1.10.28。处理游戏内测试中玩家反馈的五项问题与要求。新规则先作为纯 Java 类在离线测试 `verify-si1129`（`Harness1129`，29 项）中与旧做法比较，只采用确认有改进的部分；与要求不同的地方见第 7 节。

## 1. 量子套装与 MFSU 升级组件的配方（蓝波顿水晶）

- 原因：量子头盔 / 胸甲 / 护腿 / 靴子与 MFSU 升级组件的配方使用了“蓝波顿水晶充电电池”（`normal/item_lamacrystal_chargebat_lev0`）。IC2 1.12.2 的 `shaped_recipes.ini`（第 59、60、305～311 行）中为 `ic2:lapotron_crystal@*`，即“蓝波顿水晶”（任意电量）。
- 同样的问题也存在于**物质生成机**（`shaped_64_mass_fabricator`，IC2 第 210 行），一并修正。
- 六个配方只改这一格（`normal/item_lapotron_crystal_lev0`），图案与产物不变（`work-1129/edits/recipes_1129.py`）。仍使用充电电池的配方只剩它自己的配方与等离子发射器（SI 原创，IC2 中没有）。标签 `c:crystals/energy` 本来就只含蓝波顿水晶；指南的配方由 `<RecipesFor>` 生成，无需修改。

## 2. 方块切割机的木材（`WoodPlanks`）

- 原因：`block_cutter/logs_to_planks` 把 `#minecraft:logs` 的所有原木都切成**橡木木板**（产物固定），竹块与模组木材不在其中。
- 配方新增可选字段 `"wood": true`（数据包编解码与网络同步）。木材配方的产物改为**该原木自己的木板**：在合成配方中查找“结果属于 `#minecraft:planks`、只有一个材料且该材料接受此原木”的配方（按配方 ID 排序，取木板最多的一个），切割机给出合成台的 1.5 倍：配方的数量 6 表示“每 4 块合成木板给 6 块”（IC2 1.12.2 `block_cutter.ini`：原木 → 6 块木板，手工为 4 块）。没有木板配方的输入不匹配（不会再切出橡木木板）。
- `logs_to_planks.json` 的材料改为 `#minecraft:logs`、`#minecraft:bamboo_blocks`、`#c:stripped_logs`。对照原版 1.21.1 的资源（`tools/wood_audit_1129.py`）：橡木、云杉、白桦、丛林、金合欢、深色橡木、红树、樱花的原木 / 木头 / 去皮变种，绯红与诡异的菌柄 / 菌核 → 各自的木板 ×6；竹块 → 竹板 ×3（手工 2 块）。SI 的橡胶木 → 橡胶木板 ×6（之前为橡木木板）。其他模组的木材只要有“1 个原木 → 木板”的合成配方即可使用。
- 每个配方管理器建立一次查找表（弱引用），重载后配方对象更换时自动重建（客户端在重载时只替换配方，表以其中一个配方对象为标记）。JEI / EMI 把木材配方展开为每种木材一条（原木 → 对应木板与数量）。

## 3. 交易面板的数字输入（`NumberBox`）

- 报告：期货机的数量输入框（多 / 空等）键盘没有反应，改动的数字很久才反映。游戏内未能重现，以下为代码中找到的原因（离线用 1.21.1 `EditBox` 的插入规则建模）：
  - 点击输入框只移动光标、不选中原有数字，而输入框的位数很少（期货数量 4 位、初始“16”）。输入框满时（如“1024”、“100000”）键入的数字被静默丢弃，看起来就是“键盘没有反应”；在“16”后键入 100 得到“1610”，面板按 min(1024, 1610) = 1024 计算。
  - 点击 +/− 或任何按钮都会让输入框失去焦点，之后键入的数字不进入输入框（出售页上悬停在格子上时数字键会交换快捷栏）。
  - 窗口大小改变时面板重新初始化，输入的数值被重置为默认值。
  - 面板的刷新请求（每秒一次，以及每次翻页、选择市场、出售箱变化时）与交易操作共用一个速率限制（12 次，每 4 tick 恢复 1 次），快速操作后的点击可能被静默丢弃。离线 10,000 个 2 分钟的随机会话：292,717 次操作中被丢弃 7,294 次（2.492%）；“拖动 18 格出售箱后立刻点两次‘立即出售’”的场景丢弃 1 次。
- 修正：新的数字输入框 `NumberBox`（期货机面板 8 个、交易终端 6 个）：
  - 点击获得焦点时选中全部数字，键入即替换；位数足够容纳上限，超过上限时立即显示为上限（面板显示的就是要发送的数）。
  - 全角数字（输入法）按数字处理；鼠标滚轮与 ↑↓ 键增减（Shift ×64、Ctrl ×10）；+/− 按钮保持焦点并选中数字。
  - 键入的字符直接交给获得焦点的输入框；窗口大小改变时保留已输入的数值。
- 速率限制：刷新请求改用单独的 `EXCHANGE_VIEW`（10 次，每 4 tick 恢复 1 次），交易操作仍为 `EXCHANGE`；操作被丢弃时在动作栏提示“操作过于频繁”。出售箱 / 结算容器的变化最多每 4 tick 请求一次。离线：被丢弃的操作 7,294 → 0，刷新请求 2,346,957 → 1,696,753（−27.7%）。

## 4. 货币账户（`CoinAccount`）

- 交易所邮箱中的货币即为**货币账户**（与 UU 账户相同的概念）。
- **支付**：购买、买单的冻结、委托的报酬与手续费、期货保证金从物品栏与账户**合计**支付（`takeCoins`）：通常物品栏优先、不足部分用账户；**银行模式**下账户优先。之前只能用物品栏中的货币，而物品栏最多容纳 36 × 9,999 = **359,964** 枚，超过的单笔支付无法进行（离线 200,000 次随机操作中有 4,514 笔这样的支付，现在都能完成）。
- **收入**：通常进入物品栏、放不下的进入账户（同之前）；银行模式下销售所得、退款、悬赏与委托报酬全部进入账户，大额交易不会塞满物品栏。银行模式下“领取”只领取物品，货币留在账户。
- **存取**：“订单与邮箱”页新增账户栏：数量输入框（0 = 全部）、“存入”（物品栏的货币）、“取出”（放得下多少取多少）、银行模式开关；大宗结算页新增“货币存入账户”（容器中的货币，期货机与交易终端都有）。面板顶部显示“手持 / 账户”两项货币，银行模式时标记 B。
- 交易终端的所有者货币、个人卡画面的“邮箱货币”改称账户。离线：1,000,000 次随机支付的拆分全部正确（不足时不扣任何一方）；8 名玩家 200,000 次存入 / 取出 / 支付 / 收入，货币“期初 + 收入 − 支出 = 期末”完全一致，任何余额不为负。

## 5. 最低价批量出售（`MinPrice`、`SellDepth.maxForItemPrice`）

- 设定**最低单价**（每件货币，或无卖压买价的百分比），立即出售时按卖出曲线求出“每件价格仍不低于最低价”的最大数量 Q*，**一次成交、一次支付合计金额**（只在最后取整一次）。卖出曲线每件按相同比例下降，Q* 由一次对数求出（`maxForItemPrice`），不逐件计算。
- 适用范围：出售页与大宗结算页的“立即出售”（之前固定为 1 货币，最低价只用于集中清算）、交易终端大宗结算的出售、交易终端的“立即出售 / 其余回收”常设订单（可设为百分比，每次运行时按当时的价格换算为货币）、下单面板的卖单（限价可切换为百分比）。集中清算的最低价仍为平均价的百分比；以货币设定时按无卖压买价换算为百分比（向上取整）。
- 预览：服务器在视图中发送所选市场、出售箱与容器中商品的曲线（`CurveLine`），面板在本地计算每种商品的 Q* 与金额，输入时立即更新；下单面板显示“市场即时：Q* / 数量、金额（均价）”，悬停显示最后一件与下一件的价格。交易终端订单的提示显示当前限价与出售缓冲区余量的估算。
- 用户的例子（每件约下降 8%，最低价 1,100）：各件价格 1,300.0 / 1,200.1 / 1,107.8 / 1,022.6 …，卖出 3 件，一次支付 3,607（均价 1,202.3）。
- 离线（200,000 条随机曲线）：最后卖出的一件不低于最低价、下一件低于最低价，无例外；闭式解与逐件计算在 101,718 个案例中完全一致；一次支付 ≥ 数量 × 最低价；与逐件出售（每件取整）相比多得 0.014%，便宜的商品差距更大（买价 4.7、500 件：逐件 617，一次 878）。100,000 件时闭式解约 0.1 微秒，逐件计算约 3 毫秒。

## 6. 界面、语言与指南

- 期货机面板：出售页与大宗结算页的最低价一行（数值、c / % 切换、其余回收）；订单票的 c / % 切换与市场估算；“订单与邮箱”页的账户栏；期货页显示支付来源。交易终端：订单编辑器的 c / % 切换、订单提示的估算、大宗结算的最低价与“货币存入账户”。
- 交易终端缓冲区页的结算栏重新排列（两个按钮一行）：0.1.10.27 起“卸出”按钮（y = 139）被“输出模式”按钮（y = 141）覆盖而无法点击。
- 语言：`tools/lang_1129.py`（39 个键 × en / zh / ja：新增 34 个，改写已有的 5 个）。指南（`tools/data_1129.py`）：《期货交易机》货币账户、最低价、数字输入框；《交易终端》百分比最低价与结算；《方块切割机》各种木材的木板。

## 7. 与要求的差异、未采用的部分

- **“一个一个计算”**：0.1.10.25 起立即出售已经用闭式解一次求出数量并一次支付（`maxForMarginal`）；不足的是出售箱与大宗结算无法设定最低价（固定 1 货币）以及没有预览。本版补上了这两点。
- **以“每件自身的价格”判断**：之前判断的是“每件开始时的买价 ≥ 限价”，最后一件的实际价格（买价在该件期间的平均）可能略低于限价。离线 161,946 次出售中有 46,486 次（28.7%）最后一件低于限价，最低为限价的 0.98607。现在改为每件自身的价格 ≥ 最低价（每笔最多少卖 1 件），满足“最后一件的单价不低于最低价”的要求；下单面板的限价与交易终端订单同此规则。`maxForMarginal` 保留（公开的纯函数）。
- **百分比的基准**为无卖压买价（与集中清算的最低价相同），不是当前买价：以当前买价为基准时，卖压已压低价格的市场仍会继续卖出。离线：买价 1,250、最低 90%（1,125）时，卖压 30 卖出 16 件，卖压 300（买价 932.6）不卖。
- **不设单独的“账户”存储**：沿用邮箱的货币（存档不变），已有的邮箱货币直接成为账户余额。非银行模式下支付也会在物品栏不足时使用账户（之前需要先“领取”）。
- **键盘问题未在游戏中重现**：第 3 节的原因来自代码与离线模型。若仍出现，可能与输入法有关：输入法开启时数字在按 Enter 确认前不会送到游戏（全角数字现在可以识别）。
- **未采用**：账户之间的转账（交易所内的玩家交易已有订单簿与委托）；卖出时按逐件取整支付。
