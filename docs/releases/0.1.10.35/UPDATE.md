## 1. 加工品的收购价（0.1.10.34 的差异 1）

- **原因（测量）**：0.1.10.34 的三条加工套利（精炼铁锭 +131.0、电路板 +121.1、高级合金锭 +167.4，每件）都从市场国库买**粗矿**开始：粉碎机把 1 个粗矿变成 2 个粉碎矿石（2 个锭）。同样的翻倍也使铁锭 +106.6、铜锭 +59.9、青铜锭 +40.7（0.1.10.25 起就存在）。只改三个收购价无法消除粗矿的途径：精炼铁锭需要收购价 82 以下，低于铁锭本身的买价 194。另外各商品的价格每天各自波动，固定的收购价在部分日子仍会打开套利（见下表“不设上限”）。
- **三项修改**：
  1. **`sell_only`**（新的商品键）：`true` 时市场只收购、不出售该物品（国库库存与进口都不卖，供应为 0，卖价显示“-”并在提示中说明）；玩家之间的盘口照常。默认的粗铁、粗铜、粗金设置了此项。
  2. **`made_from`**（新的商品键，`BidLinks`）：制作该物品所用的市场货品与数量。市场的收购价不超过当天从市场买入这些原料的价格（Σ 数量 × 原料价格 × (1 + 价差/2)）；某个原料不是市场货品时不设上限。默认：精炼铁锭 ← 铁锭 1；电路板 ← 红石 2、铁锭 1、铜锭 2、橡胶 6（配方：6 根导线 = 橡胶 6 + 铜锭 2，红石 2，铁板 1）；高级合金锭 ← 铁锭、青铜锭、锡锭各 1.5（配方：3 + 3 + 3 块板 → 2 个）。出售箱、集中清算、卖出深度曲线、旧期货交易机、API 的 `quoteSell` 都使用同一个上限。
  3. **`bid_price`**：精炼铁锭 220 → 205、电路板 650 → 760、高级合金锭 600 → 665，使基础价格下的收购价位于“卖出原料”（B）与“买入原料”（A）之间。

| 基础价格下（每件） | 收购价 | 买入原料 A | 卖出原料 B | 买原料→加工→卖出 | 自有原料→加工→卖出（与直接卖原料相比） |
|---|---|---|---|---|---|
| 精炼铁锭 400 / 205 | 198.8 | 206.0 | 194.0 | −7.2 | +4.8（收购价的 2.4%） |
| 电路板 900 / 760 | 737.2 | 762.2 | 717.8 | −25.0 | +19.4（2.6%） |
| 高级合金锭 800 / 665 | 645.1 | 664.3 | 625.7 | −19.3 | +19.4（3.0%） |

- **离线模拟**（`Harness1135`，20,000 个交易日，各商品价格按市场的随机游走各自变动）：买原料、加工、卖出有利可图的天数（括号内为每件最大利润）：

| 波动 | 方案 | 精炼铁锭 | 电路板 | 高级合金锭 |
|---|---|---|---|---|
| ×1 | 0.1.10.34 的收购价 | 13,272（78.6） | 400（87.1） | 1,529（113.6） |
| ×1 | 0.1.10.35 的收购价，不设上限 | 8,465（62.8） | 10,808（209.9） | 8,664（186.6） |
| ×1 | **0.1.10.35（含 `made_from` 上限）** | **0** | **0** | **0** |
| ×3 | 0.1.10.34 的收购价 | 12,798（215.1） | 6,626（458.4） | 7,008（519.8） |
| ×3 | **0.1.10.35（含上限）** | **0** | **0** | **0** |

  自有原料加工后卖出（与直接卖原料相比）的平均差额：波动 ×1 时精炼铁锭 −0.1、电路板 +23.9、高级合金锭 +12.6；×3 时 −12.4 / −2.3 / −20.4。即加工只在基础价格附近留下 2～3% 的加工差额，价格偏离时可能低于直接卖原料。
- **全配方套利检查**（`work-1135/audit/arbitrage_1135.txt`，基础价格，国库模式）：12 条 → 6 条。消除的有铁锭、铜锭、青铜锭、精炼铁锭、电路板、高级合金锭。剩下的 6 条都需要大量 EU：煤 +13.2（每件 60,000 EU）、钻石 +750.4（2,364,000 EU）、金锭 +274.7（1,000,000 EU）、金苹果 +517.7（8,000,000 EU）、铱 +2,704.0（9,000,000 EU）、银锭 +177.7（500,000 EU）。进口模式 6 条 → 6 条（UU 物质 / 大量 EU 的途径）。
- `Round1134GameTests` 中精炼铁锭收购价的预期值相应改为 205。

## 2. 委托与挂单按小时计时（后续第 3 项，Q13，`CommissionHours`）

- **时钟**：主世界的 `gameTime`（服务器运行的 tick），1 小时 = 72,000 tick，即每秒 20 tick 时的 1 个现实小时。`/time set` 与睡觉不影响；服务器停止（单人游戏暂停）时不走；服务器卡顿时比现实时间慢。1 小时 = 3 个市场日（24,000 tick）。
- **委托**：发布时选择 1、3、6、12、24、48、72、168 小时（表单的 − / + 按这些档位切换，也可以直接输入），默认 `commissionDefaultHours`（24），上限 `commissionMaxHours`（168）。到期时未支付的奖励退回发布者的邮箱。委托行显示“剩余 5 小时 12 分”，不足 3 小时时变为警告色。0.1.10.34 及更早的委托保持原来的市场日期限。
- **新委托的通知**：发布时在聊天栏通知所有在线玩家（发布者除外）：物品、数量、奖励、发布者与时长。每个玩家可以在委托表单标题行的“通知：开 / 关”关闭。
- **盘口挂单**：挂单有效 `orderHours`（72）小时（之前 7 个市场日），挂单页显示剩余小时；到期时托管的货币或物品退回邮箱。旧挂单保持 7 个市场日。
- 每 200 tick 检查一次到期。

## 3. 国库储备（后续第 4 项，Q14，`ReserveRules`）

- **进入储备**（之前销毁）：以货币计价的盘口交易手续费、委托的发布费、悬赏的刷新费、商店的发布费、维护费与货币交易手续费。
- **上限** = `reserveWeeks`（4）× 7 × 每日普通悬赏发布数（6 + 4 (活跃人数 − 1)）× `bountyNormalValue`（4,000）× 普通倍率（1.15）：1 人 772,800，16 人 8,500,800。超过上限的部分照旧销毁；`reserveWeeks` 为 0 时不设储备（与 0.1.10.34 相同）。
- **支出**：悬赏的货币奖励先由储备支付，只有不足部分是新发行的货币。
- **账本**：另记 `ReserveIn` / `ReserveOut`。稳定器、`/mio_icif market ledger` / `audit`、国库页与 API 的 `ledger` 按进入 / 退出流通计算（发行 = 新货币 + 储备支出，销毁 = 销毁 + 存入储备），与 0.1.10.34 的含义相同。国库页底部显示“储备 N（上限 C）”，提示中显示本市场周的存入、支出与新发行。
- **离线模拟（28 天）**：

| 情况 | 手续费 | 悬赏货币 | 其中来自储备 | 新发行 | 销毁 | 储备（最终 / 最高） |
|---|---|---|---|---|---|---|
| 手续费少 | 79,882 | 585,794 | 79,882（13.6%） | 1,334,834 → 1,254,952 | 808,183 → 728,301 | 0 / 0 |
| 手续费多 | 1,608,848 | 545,833 | 545,833（100%） | 1,365,356 → 819,523 | 2,259,811 → 967,347 | 746,631 / 761,394 |

  两种情况下每天的流通量变化都与 0.1.10.34 完全相同（储备对流通是中性的），储备从不超过上限。变化在于悬赏的货币先来自回收的手续费（国库页可见），储备之后也将用于债券利息（0.1.10.37 以后）。

## 4. 玩家商店（后续第 5～8 项，Q15 / Q16，`ShopRules`、`Shops`）

- **商店**：每人一家（发布第一个报价时开店），最多 `shopMaxOffers`（12）个报价，仓储 `shopStacks`（54）组：报价的库存与收益箱合计，按各物品的最大堆叠数计组。服务器最多 1,024 家商店。商店的物品与货币保存在交易所数据中（没有方块）。
- **报价种类**（1 次交易 = 商品数量 ↔ 支付物品数量或价格）：
  - **以物换物**：店主预存商品；顾客交出支付物品（进入收益箱），得到商品。无手续费。
  - **出售**：店主预存商品；顾客支付货币，得到商品；店主的货币账户得到价格 − 手续费（`exchangeFee`，1%）。
  - **收购**：店主预存货币（次数 × 价格）；顾客交出物品（进入收益箱），得到价格 − 手续费。
  - 只限普通物品（无数据组件，与邮箱相同），货币不能作为商品或支付物品；数量 1～9,999，价格 1～999,999,999，库存最多 1,000,000 次。
- **顾客**：按整次交易 x1 / xN（数字框）/ 最大（库存、仓储空间与顾客的物品或货币中最少者）重复交易。支付物品可以来自背包，或结算槽中的容器（店内的“背包 / 容器”切换）；货币总是来自背包与货币账户。
- **店主**：补货、暂停 / 恢复、下架（库存退回邮箱）、领取收益箱（放不下的进入邮箱）。
- **费用**（全部进入国库储备）：发布费 `shopOfferFee`（50，同时支付第一个市场周的维护费）；维护费 `shopUpkeepPerWeek`（10）每个报价每市场周从店主的货币账户扣除，付不起的报价暂停，恢复时支付。
- **不在线**（Q16）：服务器运行日 = 服务器运行过的日历日（服务器本地日期；停服的日子不算，时钟往回调也不算）。店主连续 `shopIdleDays`（7）个运行日未上线：列表中排到最后（“店主离开”），仍可交易；`shopCloseDays`（30）个：商店关闭，库存、收购用的货币与收益全部退回店主的邮箱，下次登录时收到消息。
- **列表**：委托页标题下的“委托 / 商店 / 我的商店”切换。商店列表按最近交易排序（离开的店主在最后），可用背包中的物品筛选出售、收购或交换该物品的商店；打开商店显示其报价与交易按钮。“我的商店”为报价表单（种类、商品与数量、支付物品与数量或价格、库存次数、发布 (50)）与概要（报价数、仓储 x / 54、收益、领取）。
- 商店的货币交易计入 0.1.10.33 起的交易记录（0.1.10.36 的排行榜使用）。每个操作消耗一次交易的 EU。
- **测试中发现并修正**：可交易次数原来用二分查找，但仓储组数随次数并不单调（例如 64 个珍珠换 1 颗钻石时有时会腾出一组），在 20,000 个随机商店中有 59 个给出的次数少于实际可交易次数；改为从上限向下逐一检查后为 0。

## 7. 与方案的差异

- **粗矿只收购（`sell_only`）**：方案与答复中没有这一项。只改三种加工品的收购价无法消除粗矿翻倍的途径（见第 1 节），而该途径也是铁锭 +106.6、铜锭 +59.9、青铜锭 +40.7 的来源。玩家之间仍可在盘口买卖粗矿；数据包可以把 `sell_only` 改回 `false`。
- **收购价的动态上限（`made_from`）**：答复要求调整 `bid_price`；由于价格各自波动，只调整固定值时 20,000 天中仍有 8,465 / 10,808 / 8,664 天可以获利，因此另加上限（0 天）。
- **时长的“现实时间”**：按批准的 Q13 使用服务器运行时间（`gameTime`）：每秒 20 tick 时与现实时间相同，但停服期间不计、卡顿时变慢。若需要按现实时钟（停服期间也计时），可以在以后的版本改为墙上时钟。
- **维护费的“周”是市场周**（7 个市场日，不睡觉时约 2 小时 20 分服务器时间），与悬赏的周相同：12 个报价每市场周 120 货币，服务器连续运行 24 小时约 1,234 货币。若希望按现实的一周（168 小时）收取，可以改为按 `gameTime` 计。
- **结算容器的交易**：方案只写了从背包交易；本版在店内加了“背包 / 容器”切换，从结算槽的容器支付物品（`SETTLE_SHOP`）。
- **账本的显示**：面板、命令与 API 的“发行 / 销毁”按流通计算（含储备的收支），与 0.1.10.34 的数字含义相同；储备本身另行显示。
- **截断的文字增加**（48 种状态，0.1.10.34 为 32 种）：426×240 时英文 398 处、日文 336、中文 312（0.1.10.34：227 / 173 / 166）；960×540 时 245 / 105 / 76（222 / 80 / 54）。提示中都有全文，数字截断为 0。
