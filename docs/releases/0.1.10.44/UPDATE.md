# 0.1.10.44 更新说明与游戏内测试清单：电网性能与 FE 互通（阶段 0）

基于 0.1.10.43。电网性能与互通提案（2026-11-02 审计，Q1–Q12 全部按推荐方案批准）的阶段 0：

| 项目 | 内容 |
|---|---|
| 触电预检（P-1） | 裸线输送也使用路径档案；只在路径附近有活体时计算触电暴露 |
| 路径档案（P-2） | 导体信息按连通分量缓存在数组中，降低档案未命中时的重建成本；容量不变 |
| 外部 FE 发现（P-5） | 电网旁的方块改变立即探测；完整扫描之后为慢速扫描；探测不再创建能力缓存 |
| 端口列表（P-6） | FE 输出与输入两轮复用原生结算的端口列表 |
| 哈希（P-7） | 拓扑键、区块键、导体图与接收端索引的哈希修正 |
| 共用输入额度（I-3） | 原生 EU 与 FE 共用机器每 tick 的额定输入（按规格修正，唯一的规则变化） |
| 缓存（I-4） | Mekanism 比率每 tick 读取一次、严格能量视图复用；导线保留的 FE 适配器使用能力缓存 |

改动在工作区中，未提交。除 I-3 外规则不变。本文按项目列出改动，每节后附游戏内测试步骤与预期结果。

## 0. 测试准备

- **世界**：创造模式，开启作弊（`/mio_icif perf` 需要权限等级 2）。
- **配置**：没有新增配置。使用默认配置（独立电网，线损默认 `LOSSLESS`）。
- **诊断指令 `/mio_icif perf`**：
  - 每个维度一行：电网结算的中位、p95、最大值（ms）与路由计划的新建 / 续用 / 预算用尽次数。
  - “自启动以来”：送电次数，其中经电缆的“路径档案”次数与“逐格遍历”次数。
  - “FE 每 tick”：推入导线、输出、输入与邻居探测次数。
- **其他模组的 FE 方块**：第 2、4 节需要能存储或产生 FE 的其他模组方块（例如 Mekanism 的能量立方、Thermal 的能量单元、Powah 的电池）。没有时跳过这两节。
- **大电网**（第 5 节，可选）：用 `/fill` 铺设线缆，例如 `/fill ~ ~ ~ ~63 ~ ~63 mio_icif:wiring/cable/block_tin_cable_1`（4,096 根）。

## 1. 触电预检与路径档案（P-1、P-2）

### 改动（`IndependentSiEnergy.java`、`ConductorRegistry.java`）

- **裸线输送**：电压高于线缆绝缘时（裸线），0.1.10.43 每次输送都逐格遍历路径以寻找触电暴露。0.1.10.44 也使用路径档案：暴露由档案按路径顺序给出，只在路径附近（导体中心 ±1.5 格）有活体（非旁观者）时才计算。附近没有生物时，原来的遍历找到的暴露也不会伤害任何人，因此结果相同。
- **附近的生物**：每次结算只收集一次（导体所在及相邻区块中的活体）。
- **档案的导体信息**：方块实体、熔断上限与特殊线缆按连通分量保存在数组中，重建档案时不再逐格查询区块。导线方块改变、熔断或剥离时清空。
- **容量不变**：`PATH_PROFILE_LIMIT` 8192、`PLAN_CACHE_PLANS` 64。档案按路径（源 × 接收端）缓存，16k 梳状电网有 462,240 条路径，提高容量不可行（与提案的差异，见第 7 节）。

### 测试

1. 用 6 根裸锡线（`block_tin_cable`）连接一台发电机与一台机器，周围 3 格内没有生物（玩家自己也站在 3 格以外；创造模式的玩家也算活体）。执行两次 `/mio_icif perf`，间隔约 10 秒。**预期**：“路径档案”次数增加，“逐格遍历”次数几乎不增加。
2. 站在裸线上（生存模式）或在线旁放一头牛。**预期**：受到触电伤害，与 0.1.10.43 相同。离开 2 格以上：不再受伤。
3. 绝缘线（`block_tin_cable_1`）旁放一头牛，然后把其中一格换成裸线。**预期**：换成裸线后，牛在 1 秒内开始受伤（档案重新读取了导线）。
4. 熔断：用低等级裸线输送高电压。**预期**：线缆熔断与 0.1.10.43 相同。

## 2. 外部 FE 发现（P-5）

### 改动（`IndependentSiEnergy.java`、`FECompatTile.java`、`mio_icif_wire.java`、`FECompatAPIImpl.java`）

- **方块改变立即探测**：电网旁边的位置在方块改变、收到邻居更新或方块实体加载时，下一次结算立即探测（每 tick 最多 128 个位置；排队超过 16,384 个时改为完整扫描）。
- **完整扫描与慢速扫描**：电网改变后，完整扫描检查所有锚点的六个邻居（每 tick 128 个锚点，与 0.1.10.43 相同），只运行一遍；之后为慢速扫描，每 tick 8 个锚点，用于发现没有方块改变就出现的能力。
- **探测不再创建能力缓存**：0.1.10.43 的每次探测创建三个能力缓存，每个缓存在世界中注册监听器（4,000 根线缆时累积 523,000 个监听引用）。探测现在实时查询；导线与 `IFECompatAPI.getStorage` 保留的适配器调用 `retain()` 后才使用缓存。
- 1k 电网每 tick 的探测次数从约 25.8 降到 15.8（离线基准）。

### 测试

1. 铺一条至少 20 格的 SI 线缆，一端接 MFSU（充满）。等待 10 秒后，在线缆中间旁边放置其他模组的 FE 电池。**预期**：1 秒内开始充电。
2. 拆除 FE 电池再放回。**预期**：再次在 1 秒内开始充电。
3. `/mio_icif perf` 的“邻居探测”：电网不变时比 0.1.10.43 少（离线基准的 1k 电网：每 tick 约 25.8 → 15.8）。
4. 长时间运行（例如 30 分钟）后内存不再随线缆数量持续增长（可选，用 F3 观察）。

## 3. 端口列表与哈希（P-6、P-7）

### 改动（`IndependentSiEnergy.java`、`PlatformTopology.java`、`ConductorGraph.java`、`ReceiverContacts.java`、`ConductorRegistry.java`）

- **端口列表**：FE 输出与输入两轮复用原生结算的端口列表（源重新报价，接收端读取实时账本），不再每 tick 额外构建两次。端点编辑后回到完整扫描。
- **拓扑键**：`PlatformTopology.Key` 的坐标哈希改用 `HashCommon.murmurHash3`。0.1.10.43 中，1,000 根线缆的梳状电网的 1,318 个位置约有 42–60%（随世界对象的身份哈希而变）落在 8 个以上的桶中。（`HashCommon.mix` 截断为 int 后与 HashMap 自身的扰动相互抵消，不能使用。）
- **区块键**：导体注册表的区块键用 fmix64 混合，电网的区块计数改用 fastutil 的混合哈希表（`Long.hashCode` 为 `x ^ z`，8 × 8 区域的区块只落在 8 个桶中）。
- **导体图**：重复链接的检查改为排序（规则不变：重复或自环仍然拒绝）。
- **接收端索引**：不可修改视图代替 `Map.copyOf`（线性探测在 16k 电网上每次未命中约 1.6 µs，占服务器线程的 18%）。

### 测试

1. 普通电网（发电机、线缆、机器、储电箱）：送电、熔断、变压器与保护线缆与 0.1.10.43 相同。
2. 加载与卸载区块（远离后返回）：电网恢复送电。

## 4. 共用输入额度（I-3，规则变化）

### 改动（`FeLedger.java`、`FeMachineBridge.java`、`IndependentSiEnergy.java`）

- **规则**：机器每 tick 的额定输入（`maxReceive`）由原生 EU 与 FE（以及整 EU 物品输入与焦耳输入）共用。0.1.10.43 两边各有一个 `maxReceive`，从两侧同时供电的机器每 tick 最多收到额定输入的两倍。
- **原生 → FE**：引擎把原生入账报告给机器的 FE 账本，本 tick 的 FE 额度减去这部分（向上取整到整 FE；4 FE = 1 EU）。
- **FE → 原生**：公平分配模式（默认）下，原生额度减去本 tick 已收到的 FE。
- **存档**：引擎为此取得每个原生接收端的 FE 桥，原来没有 FE 桥的机器此后保存 `scex_fe_uncertain_output: 0`（读取不受影响）。
- **对 FE 取入的影响**（离线基准 fe_mixed_1k：120 个各存 50,000 FE 的外部电池向原生电网供电）：已收到原生 EU 的接收端在同一 tick 能取入的 FE 减少，电池放电变慢；6,000 tick 计测窗口开始时剩余 472,282 FE（0.1.10.43：260,452），窗口内的取入为 55.8 FE/tick（31.7）。只关闭 I-3 时为 28.6 FE/tick、剩余 242,732 FE，与 0.1.10.43 一致，因此差异全部来自 I-3。FE 输出不变。

### 测试

1. 一台 SI 机器（查看其额定输入）同时连接 SI 发电机（经线缆，原生 EU）与其他模组的 FE 发电机。让两边的供电都超过额定输入。**预期**：机器每 tick 收到的能量不超过额定输入（0.1.10.43 最多为两倍）。
2. 只用 FE 供电。**预期**：机器以额定输入充电（与 0.1.10.43 相同）。
3. 只用原生 EU 供电。**预期**：与 0.1.10.43 相同。

## 7. 与提案的差异

- **P-2**：没有提高缓存容量。档案按路径缓存，16k 梳状电网的工作集为 462,240 条路径（不限容量时实测），提高容量不可行；改为降低未命中时的重建成本。由于共享 BlockPos，最坏情况下的档案内存估计也较低（16k：约 40 MB，原估计约 98 MB）。
- **分配量**：目标为 −50% 以上，只在裸线电网达到（comb_1k_bare 1,867 → 516 KB/tick，−72%；comb_16k_bare 76,284 → 17,986，−76%）；绝缘线电网为 −8%（comb_1k 563 → 516）到 −45%（comb_16k 32,721 → 17,949）。
- **P-1**：提案为“岛的外接箱中有无生物”；实现按每条路径的触电范围检查，更精确。
- **P-5**：慢速扫描每 tick 只检查 8 个锚点，没有方块改变就出现的能力被发现得更慢（4,000 个锚点最多 500 tick）。
- **I-3**：原生额度扣除 FE 只在公平分配模式下进行。FE 取入的变化见第 4 节。
- **I-4**：Mekanism 比率按服务器 tick 缓存（配置重载从下一 tick 生效）。
- **导体图**：同时有重复链接与未知 ID 时，拒绝信息现在是未知 ID 的那一条（仍是 `IllegalArgumentException`）。
