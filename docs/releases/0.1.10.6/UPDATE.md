# 0.1.10.6 更新说明：修复与改进补丁（11 项：物流死循环、超频调节、拔刀剑显示、流体机器、作物）

基于 0.1.10.5（`pr-0.1.10.5-20261018`）。处理实机测试与玩家报告的 11 项问题与改进请求。构建环境为 Gradle 8.10.2、JDK 21、NeoForge 21.1.218，离线构建。

## 1. 弹出／抽入升级的无限循环

**现象**：打粉机与电炉相邻，两台都装抽入与弹出升级，旁边放一个箱子：同一批物品在两台机器之间来回传递，永不进入箱子。

**原因**：未设定方向的弹出升级按固定的面顺序选择第一个能接收的邻居，机器排在箱子前面；而对方机器的抽入升级又把物品抽回去。

**修复**（`AbstractProcessingMachineBlockEntity`，弹出、抽入与 IC2 观测路径三处都适用）：

* **存储优先**：未设定方向时按“存储 → 其他方块 → 机器”的顺序尝试（同类之内保持原顺序）。存储为方块标签 `mio_icif:automation/storage`（默认：`#c:chests`、`#c:barrels`、`#minecraft:shulker_boxes` 与 SI 的 6 种储物箱）以及箱子、木桶、潜影盒的方块实体；机器为方块标签 `mio_icif:automation/processor`（默认为空）、所有 SI 加工机器、熔炉类与酿造台。
* **防来回传递**：
  * 机器不会把物品弹出到最近 200 tick（10 秒）内从中抽入过的机器；
  * 不会从自己最近弹出过的机器抽入；
  * 不会弹出到弹出口正朝向自己的相邻机器。
* 存储邻居从不受限：从箱子抽入、再弹出回同一个箱子的用法照常工作。
* 设定了方向的升级仍按设定的面工作（同样受防来回传递保护）。

## 2. 装超频升级的回收机进度不显示

**原因**：超频后每 tick 进度为 ⌈1/0.7ⁿ⌉，回收机的 45 tick 加工在 3～4 个超频下只需 1～2 tick：加工在同一 tick 内完成并把进度清零，客户端同步到的永远是 0，进度条、百分比与剩余时间都不动。机器本身的速度是正确的。

**修复**：

* 新方法 `getDisplayProgress()`：加工完成后的那一 tick 返回满进度，界面能看到完成的瞬间。
* 所有机器菜单（`mio_icif_machine_menu`）同步显示用进度而非原始进度；回收机、批量合成机、炼油机的容器数据同样改用它。
* 8 个数据下标 0 不是进度的菜单（造水机、电力热能发电机、流体热交换机、冷凝器、流体分配器、感应炉、太阳能蒸馏器、蒸汽发生器）用 `progressDataIndex()` 指定正确的下标或不参与。
* 新方法 `getDisplayProgressPerTick()`、`getTicksPerOperation()` 给出当前设定下的速度（供超频提示框使用）。

## 3. 新功能：超频调节滑块

* 机器装有至少 1 个超频升级时，界面左侧面板底部出现 **OC 滑块**（竖直轨道、彩色填充、滑钮，下方显示“生效数/安装数”）。
* 拖动、点击轨道或在轨道上滚动滚轮均可调节；按超频升级个数分档（0～安装数）。
* 提示框实时显示：调节百分比、生效个数、每 tick 进度与每次加工的 tick 数、能耗倍率（1.6ⁿ）与 EU/t。拖动中尚未生效的数值以“~”标出估算值，估算使用与机器相同的公式。
* 同步：客户端发送 C2S 数据包 `mio_icif:machine_overclock`（容器 ID + 百分比，服务器端限制在 0～100）；服务器只在该玩家打开的就是这台机器的有效菜单时应用。机器数据通过菜单的数据槽同步回客户端（安装数、百分比、生效数、每 tick 进度、每次加工 tick 数、EU/t）。
* 保存：NBT 键 `scex_oc_throttle`（100 % 时不写入，旧存档默认为 100 %），区块重新加载后保留。
* 规则：速度与能耗按生效个数计算；**储能加成保持全部已安装超频升级的值**，调低时不会损失已储存的电量。

## 4. 量子演算核心可以叠加

* 胸甲与护腿各装一个演算核心时，两个都生效：每个工作中的核心增加 1 条链接与 8 QB（两个时为 4 条链接、36 QB）。
* 新方法 `QuantumLinks.activeComputeCores(Player)`；链接容量与带宽预算都按工作中的核心数计算。核心状态按部件判断（开关、电量），与 0.1.10.4 的规则相同。
* 装备控制台在多个核心工作时显示“CPU×n”，纠缠矩阵底部显示“×n”。

## 5. 武装展示台上不显示拔刀剑

**原因**：拔刀剑：重锋对非玩家实体的所有手持显示上下文都不绘制任何东西（刀身由其玩家渲染层 `LayerMainBlade` 绘制），展示台的全息人偶（盔甲架）因此是空手。

**修复**：人偶渲染器新增 `BladeHandLayer`：手持物品是拔刀剑时，按原版手持物品的坐标系定位到手部，再把刀模型的刀身部分（与武装库飞行动画相同的模型与比例）以握柄在拳中、刀尖朝上前方的姿态绘制。主手与副手都支持。

## 6. 武装库的拔刀剑飞行动画

* 刀类在飞行中不再抖动，翻滚幅度降为 1/4，推进俯仰降为 30 %，飞行更平稳。
* 拔刀姿态的倾角由 30° 改为 75°，并按平滑曲线（smoothstep）随飞行进度过渡，抵达时刀身自然竖起而不是突然转向。
* **限制**：本机无法启动客户端，飞行姿态与展示台的握持角度未经游戏内确认，如有偏差请反馈截图。

## 7. 流体反应堆界面

* **热冷却液槽错位**：输出槽的液体绘制在 x = 192，而纹理中槽框内腔为 190～201，液体越出右侧槽框 2 像素。改为 190（与输入槽 10～21 对称）。刻度位置 192 本就右对齐，未改动。（已用纹理像素逐列核对。）
* **底部绿色面板的文字看不清**：面板是深绿色网格，旧文字为深灰色（`0x2A2E33`）。现在先在面板内腔（7～204 × 137～146）铺一层深色半透明底，再用带阴影的亮色文字：左侧热量（低于 50 % 浅绿、低于 85 % 琥珀、以上红色），右侧发热功率（青色）；文字过长时自动缩小。
* 移除位于 (188, 145) 的旧热量条：该处没有槽框，图集区域几乎透明，只会在物品栏右侧画出一条灰线。热量改由文字颜色表示。
* 发电模式的反应堆界面是浅色面板，文字清晰，未改动。

## 8. 牛奶疣

* 牛奶疣成为食物：可随时食用（饱食时也可），恢复 2 点饥饿值、0.3 饱和度，并像牛奶一样清除状态效果（`EffectCures.MILK`，与牛奶桶完全相同的解除范围）。物品提示说明此效果。
* 加入物品标签 `c:buckets/milk`、`c:drinks/milk`、`c:milks`、`forge:milk`：按标签要求牛奶的配方（含其他模组）都接受它。
* 新配方 `mio_icif:cake_from_milk`：与原版蛋糕同形，牛奶位使用 `c:buckets/milk` 标签，可用牛奶疣代替牛奶桶，也可混用（牛奶桶照常返还空桶）。
* SI 的咖啡配方改为使用 `c:buckets/milk` 标签。

## 9. 除草剂流体的名称

* **原因**：流体类型的显示名使用描述 ID `fluid_type.mio_icif.weed_ex`，三种语言文件都没有这个键（只有 `fluid.mio_icif.weed_ex`），储罐、JEI 等处显示为原始键名。
* **修复**：补上三种语言：Weed-EX／除草剂／除草剤。英文物品名“Weed-Ex”统一为“Weed-EX”。
* 日文语言文件此前没有任何流体类型名（显示英文），本次补全 15 种流体的日文名，以及除草剂桶、作物监管机除草剂提示等日文键。

## 10. 作物监管机无法自动输入除草剂与水（及流体机器全面检查）

**作物监管机的原因**：

* 肥料、除草剂、水容器槽只接受**顶面**的自动化输入（对齐 IC2 的 `InvSide.TOP`），从侧面接入的物品管道送不进任何东西。
* 水容器槽只认水桶与**满的** SI 水单元：半满的通用单元与其他模组的水容器被拒收。
* 除草剂槽倒空除草剂桶或单元后**直接删除空容器**（只考虑了会自行消失的除草剂罐）。
* 流体抽入升级只取相邻储罐的“第一种”流体：相邻储罐先给出水时，即使只缺除草剂也抽不到。

**修复**：

* 三类容器槽改为可从任意面自动化输入。
* 水槽接受所有能放出水的容器；除草剂槽接受作物监管除草剂与所有装有除草剂的容器（除草剂桶、单元）。
* 倒空的桶与单元进入水槽下方的输出槽（与水共用），不再删除；输出槽放不下时等待。
* 流体抽入升级按名称分别向相邻方块索取水与除草剂。
* 流体管道的流体能力本就对所有面开放，检查后未发现问题（GameTest 中验证从侧面灌入除草剂）。

**通用部件**：新类 `FluidContainerSlots`（`common.util`）：

* `peek` / `holds`：通过物品流体能力判断容器内容；
* `emptyInto`：只倒入储罐能接收的量；仍有流体的容器留在原槽（该槽只有 1 个时），倒空的容器进入空容器槽（SI 单元恢复为普通空单元以便堆叠），放不下就不处理，从不丢失容器；
* `pull`：按名称向相邻方块索取指定流体。

**全面检查的结果**（机器原有的桶／单元处理代码保持不变，只把旧代码不认识的容器交给 `FluidContainerSlots`）：

| 机器 | 问题 | 修复 |
|---|---|---|
| 流体热交换机 | 只认岩浆桶与满的岩浆／热冷却液单元：**热冷却液桶被拒收**，半满单元与其他模组容器被拒收 | 接受所有岩浆／热冷却液容器；与旧代码相同，不让两种产物在输出罐混装 |
| 流体反应堆 | 只认冷却液桶、水桶与 SI 单元 | 接受所有冷却液／水容器，空容器进入空容器槽 |
| 发酵机 | 只认满的生物质单元：生物质桶、半满单元被拒收 | 接受所有可发酵流体的容器 |
| 装罐机（倒空模式） | 只认 `BucketItem` 与 SI 单元：牛奶桶、其他模组容器被拒收 | 接受所有能放出流体的容器；倒空后消失的一次性容器无需输出槽 |
| 复制机 | 只认 UU 桶与 SI 单元 | 接受其他模组的 UU 容器 |
| 半流质发电机、流体加热机、高级半流质发电机、柴油发电机、地热发电机 | 只认桶与满单元 | 接受所有对应燃料的容器 |
| 太阳能蒸馏器、洗矿机、斯特林动能发电机 | 只认水桶与满的水单元 | 接受所有水容器 |

另外发现并修复：半流质发电机、流体加热机、高级半流质发电机、柴油发电机与斯特林动能发电机在储罐接近满时会**先把部分燃料／水灌进储罐、容器却保留**（储罐差多少就白得多少）。现在先模拟，只有整个容器能装下时才倒入。

未改动：蒸汽发生器（物品槽已按 IC2 关闭）、高炉（压缩空气单元是配方材料）、电解机（水单元是加工原料）、酿酒桶（原版只用水桶）；各机器原有的 IC2 侧面规则（例如热交换机的热流体容器仍只从顶面输入）保持不变，只有作物监管机按玩家报告放开。

## 11. 次世代作物扫描仪接受 UU 物质单元

* 基因编辑页的催化剂槽现在也接受 UU 物质单元、UU 物质桶与其他 UU 容器。容器倒入扫描仪内置的 **UU 储罐（4,000 mB）**，空容器回到玩家物品栏（放不下时掉落）。桶要等储罐能装下 1,000 mB 时才倒入。
* 1 mB UU 物质 = 1 个催化剂 = 1 个 UU 物质物品（与质量发生器的 1,000,000 EU/mB 一致）。基因编辑先从储罐扣除，不足部分再由槽中的 UU 物质物品支付。
* 储罐保存在扫描仪自定义数据中（`Scanner` / `UuMb`），通过菜单数据槽同步。催化剂槽下方新增储罐量条，悬停或空槽提示显示“UU 储罐：x / 4000 mB”与使用方法。
