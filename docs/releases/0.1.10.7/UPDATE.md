# 0.1.10.7 更新说明：服务器 TPS 改进（方案 Phase A + Phase B）

基于 0.1.10.6（`pr-0.1.10.6-20261018`）。依据服务器 JFR 汇总（`summary.json`，2026-10-16，LegacyGenesis，180 秒）与全模组代码检查形成的 TPS 优化方案，实现 Phase A 与 Phase B。构建环境为 Gradle 8.10.2、JDK 21、NeoForge 21.1.218，离线构建。

**原则**：所有改动都不改变计算结果（电力分配、线损、熔断、绝缘烧毁、电击、电表数值、存档）。只让同样的工作更省。唯一的行为差异是物品弹出／抽入升级在空闲时的等待（见 M1，可用配置关闭）。

## 背景：测量结果

* 测量期间服务器平均 tick 52 ms（预算 50 ms），实际 15.7～15.9 TPS。
* 主线程采样中 **SI 电网（`IndependentSiEnergy`）占 35.3 %**（约 18 ms/tick），超过 AE2 全体（22.3 %）。
* 电网内部：逐格遍历送电路径做熔断／绝缘／电击判定（13.8 %），其中每根导线都重新读取配置（`CoreConfig.getBool`，单独 7.0 %）；每 tick 重建全部机器的端口表（3.2 %）；路由计划的创建与推进（6.4 %）；提交前校验（2.3 %）。
* 地磁发电机、机器、物流与量子套装在该汇总的前 45 个方法中没有出现（低于 2.1 %），但代码中存在明确的浪费，一并处理。

## Phase A

### E1 电网开关缓存

* `IndependentEnergyMode` 的过载开关（过载、爆炸、熔断、电击）在配置修订号（`CoreConfig.revision()`，每次 `overrideBool` 递增）或设置方法变化之前保持缓存；`enabled()` 与 `feature()` 只读取一次启动属性。
* 分配模式、线损模型与损耗取整仍每次读取系统属性（测试按批次切换），只缓存配置部分。
* 结算中每个窗口只读取一次开关（此前每根导线读取 2～4 次）。

### E2 送电路径档案

* 每个导线快照、每条送电路径，第一次使用时记录：最低熔断上限、最低绝缘击穿值、最低绝缘吸收值、导线方块实体、特殊电缆。
* 送电电压不高于全部限值（正常运行时几乎总是如此）时，**不再逐格遍历**：遍历计数、探测电缆、通电导线、“最弱限值”都直接取自档案，结果与遍历相同。
* 高于任一限值，或路径上有未加载区块、尚无方块实体、方块实体已移除时，照旧逐格遍历并判定。发生熔断或绝缘烧毁时清空档案。档案随快照失效，最多 8192 条。
* 检查脚本以 20 万组随机路径与电压比对：档案的判定与逐格判定完全一致。

### E9 电缆不再 tick

* 独立电网控制的电缆此前每 tick 只做一件事：把“通电”计数减 1。现在“通电”改为与游戏时间比较（最近一次通电后 20 tick 内），这些电缆不再注册 ticker。大型基地中数千～数万根电缆的 tick 开销消失。
* 旧电网（未受独立电网控制）的电线照旧 tick。

### E10 管理员命令 `/mio_icif perf`

* 需要权限等级 2。显示服务器平均 tick 与 TPS；每个维度电网每 tick 的耗时（最近 256 tick 的中位数、95 百分位、最大值）与路由计划的新建／续用／预算用尽次数；启动以来的送电次数、路径档案命中、逐格遍历、空闲复用与校验复用次数。
* 用于在实际服务器上比较改动前后（本机无法启动服务器）。

### 地磁发电机（G1～G4）

* 结构检查：此前每 tick 2 次注册表查询 + 6 次方块读取。现在方块对象只查一次；在相邻天线／底座放置或移除时（天线与底座方块新增通知）、加载后以及每 40 tick（按位置错开）检查。
* 磁场值：此前在值为 0 时每 tick 读取下方最多 20 个方块。现在 0 也缓存，仍每 15 tick 刷新。
* 生物群系倍率：此前每 tick 生成字符串比较。现在首次与每 600 tick 计算一次（判定方式不变）。
* `setChanged()`：此前每 tick 无条件调用（含邻居与比较器更新）。现在只在工作状态变化时调用；只有电量变化时仅标记区块需保存。

### 物品与经验发电机

* 收集掉落物／经验球的实体搜索此前每 tick 两次。现在一次搜索为空后 10 tick 内不再搜索；有实体时仍每 tick 搜索与吸引。

## Phase B

### E3 电表采样延迟

* 每次送电对路径上每根导线写入电表采样（HashMap 合并）。现在采样按原顺序排队，在读取电表（电表、能量终端、探测电缆、API `getNodeStats`）时才加入，数值与以前逐位相同。无人读取时这部分工作完全省略。

### E5 端口扫描的区块缓存（缩小版）

* 每 tick 端口表中，每台机器都要查询区块、tick 状态与拓扑就绪。现在同一次结算内按区块缓存（结算外的查询不使用缓存；出错隔离区块时清空）。
* 原方案中“跨 tick 只更新差异”的部分没有实施：输出开关（红石）、遥控关闭、需求面等会在任意 tick 变化而没有事件，跨 tick 缓存会给出错误的面。

### E6 空闲结算复用

* 没有任何电源还有配额时，原生结算只是依次建立并丢弃各窗口的路由计划。现在第一次的结果（游标终点与计划数）按“快照、路由代次、端点编辑次数、电源数、起始游标”保存，之后直接复用，结果相同。

### E8 提交校验复用

* 同一窗口在需求准备时已校验、其后没有任何写入（tick、余额写入、端点编辑、拓扑就绪、快照都相同）时，提交不再重复整套校验。提交本身仍逐一核对被写入的储能。

### M1 物品自动化节流（唯一的行为差异）

* 物品弹出／抽入升级在一次未移动任何物品后，依次等待 4、8、16、20 tick 再尝试；机器自身物品栏变化（产出、消耗、放入）时下一 tick 立即尝试；物品在移动时仍每 tick 运行。
* 流体弹出／抽入升级不受影响（每 tick 运行）。
* 影响：从“停滞”恢复时最多延迟 1 秒（例如目标箱子被清空后）。可用配置 `Performance.automationPacing = false` 恢复每 tick 运行。

### M2 邻居分类缓存

* 0.1.10.6 的“存储优先”排序每次传输都要对 6 个面读取方块实体与标签。现在按面缓存，该位置方块变化时（能力失效通知）或最长 200 tick 后重新判断；输出槽为空时不再计算排序。

### M4 流体管道能力缓存

* 流体管道此前每 tick 对每个面查询相邻流体能力。现在使用 `BlockCapabilityCache`（方块或区块变化时自动失效）。

### S1 威胁感知仅在变化时发送

* 威胁列表此前每 5 tick 无条件发送。现在只在内容变化时发送；内容不变但非空时每 20 tick 刷新（客户端 1.5 秒后遗忘列表）；空列表不重复发送。

* 文档：指南“机器”（物品自动化节流）、“输电与储电”（电网的服务器负载、`/mio_icif perf`）（三种语言）；API 指南第 14 节（中英）。
* 工具：`tools/lang_1107.py`。
