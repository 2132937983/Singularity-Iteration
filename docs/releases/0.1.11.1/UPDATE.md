# 0.1.11.1 更新说明与游戏内测试清单：外部方块加入公平轮次与并网接口（阶段 2）

基于 0.1.11.0。电网性能与互通提案（2026-11-02 审计，Q1–Q12 全部按推荐方案批准）的阶段 2：与其他模组的能量互通。

| 项目 | 内容 |
|---|---|
| 外部方块加入公平轮次（提案 (d)） | 其他模组的方块是原生结算的端口，与 SI 端点使用同一个窗口、路由与公平分配轮次；一个电源每 tick 的输出额度由 SI 与外部接收端共用 |
| 线缆不再接收 FE（(e)） | 线缆不提供 FE 能力，收件箱删除；只推送 FE 的方块经 SI 机器或并网接口接入 |
| 电池的死区（(f)） | 其他模组的电池：充电率 ≥90% 只供电，≤10% 只充电，之间保持原角色；电池之间不来回传递能量 |
| 并网接口（(g)，Q5） | 能量转换器（ID 不变）改为并网接口：输出 / 输入 / 双向（死区 10 / 25 / 50%），上限 32–2,048 EU/t，缓存 200,000 EU |
| Mekanism 焦耳（(h)） | 焦耳视图保留不足 1 EU 的焦耳，小而持续的能量流不再丢失 |
| 线损一致（(i)） | FE 使用原生的线损模型与设置；`LOSSLESS` 时 FE 也无损耗 |
| 接触的缓存（(b)） | 每个外部方块的每个接触面保留一个适配器（能力缓存），每帧只询问一次 |

改动在工作区中，未提交。这是行为变化（各节的“改动”）。没有新增配置。存档：并网接口新增 3 个标签（`GridTieMode`、`GridTieBand`、`GridTieLimit`），旧的能量转换器加载时自动迁移（第 4 节）。

## 0. 测试准备

- **世界**：创造模式，开启作弊（`/mio_icif perf` 需要权限等级 2）。
- **配置**：默认配置（独立电网、公平分配、线损 `LOSSLESS`）。
- **其他模组**：第 1–3、5 节需要其他模组的 FE 方块：电池（既能输入又能输出，例如 Mekanism 的能量立方、Thermal 的储能器）、只输出的发电机、FE 机器。没有其他模组时只能测试第 4 节中 SI 一侧的步骤。
- **诊断指令 `/mio_icif perf`**：FE 行为“FE 每 tick：并网接口 a，输出 b，输入 c；邻居探测 d（跳过 e）”。“输出”是交给其他模组方块的 FE，“输入”是从其他模组方块取得的 FE，“并网接口”是并网接口在正面移动的 FE。

## 1. 外部方块加入公平轮次（(d)、(i)、(b)）

### 改动（`IndependentSiEnergy.java`、新增 `ForeignEndpoint.java`、`FairShareDistributor.java`）

- **一个轮次**：SI 电网旁每个带有能量能力的其他模组方块都是原生结算的一个端口。0.1.11.0 在原生结算之后用两次传递按对移动 FE（先输出，后输入），只能使用原生结算剩下的能量。现在一个电源每 tick 只有一个输出额度，由 SI 接收端与外部接收端共用。
- **只接收的方块**属于蓄电类（Q4）：在 SI 负载之后接收余量。引擎每帧每个面询问一次它能接收多少（模拟调用）。入账先进入引擎的暂存单元，然后一次交给方块；方块拒收的部分留在单元中，下一 tick 再交（端口的空间扣除这部分）。tick 之间单元中只留下不到 1 FE。
- **只输出的方块**是发电机：引擎只为已规划、可路由的输送从它提取 FE。
- **既接收又输出的方块**是电池（第 3 节）。
- **端口顺序**：外部端口均匀插在 SI 端口之间（`IndependentSiEnergy.interleave`）。原生结算的每个窗口最多 128 个接收端，所以每个窗口都按电网的比例包含 SI 负载与外部接收端，外部接收端只得到负载满足之后的余量（第 7 节第 1 项）。
- **FE 没有电压包**：来自外部方块的输送电压为 0，外部接收端不会爆炸。
- **线损**：与原生相同的模型与设置。默认的 `LOSSLESS` 下 FE 也无损耗（0.1.11.0 的 FE 传递按对计算并向上取整的损耗）。
- **接触的缓存**：每个外部方块的每个接触面保留一个适配器（`FECompatTile.retain()`，能力缓存），新放置的方块最多 3 tick 后开始收发。

### 测试

1. 发电机（例如创造模式发电机 64 EU/t）→ 线缆 → SI 储电箱（MFSU），同一根线缆旁再放一个空的其他模组 FE 电池。**预期**：两者大致平分（各约 40–60%）。0.1.11.0：FE 电池只得到原生结算剩下的一小部分。
2. 发电机 → 线缆 → SI 机器（工作中），线缆旁放一个空的 FE 电池。**预期**：先满足机器，余量才进电池。
3. 其他模组的只输出发电机旁放 SI 线缆 → 储电箱。**预期**：储电箱充电，`/mio_icif perf` 的“输入”增加。
4. 长线缆（例如 30 根锡线）一端发电机，另一端只放 FE 电池。**预期**：电池收到的 FE ÷ 4 等于发电机送出的 EU（`LOSSLESS`）。
5. 在电网旁放置一个新的 FE 电池。**预期**：1 秒内开始充电。
6. 一个电网上接 130 台以上需要电的 SI 机器与几个空的 FE 电池，发电量小于机器的需求。**预期**：电池不充电；机器都满了（或停机）之后电池才开始充电。

## 2. 线缆不再接收 FE（(e)）

### 改动（`AbstractWireBlockEntity.java`、`FECompatTile.java`、`IndependentSiEnergy.java`）

- 线缆的 `scexFeCapability` 返回 `null`：其他模组的方块不能再把 FE 推入 SI 线缆。0.1.10.39 至 0.1.11.0 期间每个面都接收推入的 FE，放进一个不保存的收件箱（区块卸载或停服时其中的 FE 丢失）。
- 只推送 FE（不提供提取）的方块直接贴在 SI 线缆上时不再供电。请把它接到 SI 机器（机器仍把 FE 收入自己的储能）或输入模式的并网接口（第 4 节）。
- 删除的内部成员：`IndependentSiEnergy.offerFe` 与 `feInputTotal`、`FECompatTile.INBOX_FE` / `offerInbox` / `inbox`、`RoutedFeTarget`、`FeMachineBridge.pushRouted` / `pullRouted`；`PerfCounters.Kind.FE_INTO_CABLES` 改为 `FE_GRID_TIE`。它们都在 `core.runtime` 中，不是公共 API。

### 测试

1. 只推送 FE 的方块（例如只向外推送的发电机）直接贴在 SI 线缆上，线缆通向储电箱。**预期**：储电箱不充电（0.1.11.0：充电）。
2. 在两者之间插入输入模式的并网接口（正面朝向发电机），或让发电机直接贴 SI 机器。**预期**：恢复供电。
3. SI 机器（例如 MFSU 的输入面）贴其他模组的 FE 线缆：机器照常接收 FE。

## 3. 电池的死区（(f)）

### 改动（新增 `StorageHysteresis.java`）

- 其他模组的电池（既能接收又能输出）每 tick 只有一个角色：
  - 充电率 ≥90%：供电方。为 SI 负载供电（蓄电顺位），不接收能量；它的能量不会给任何蓄电充电。
  - 充电率 ≤10%：接收方。接收余量，不供电。
  - 两者之间保持原角色。第一个角色：半满及以上为供电方，否则为接收方。
- 因此电池不会在同一 tick 内既充电又放电，两个电池之间也不会来回传递能量。
- 角色在每个 tick 开始时决定；一个 tick 内的数量只受方块自身速率的限制，所以速率大的电池在越过边沿的那个 tick 中可能低于 10% 或高于 90%。

### 测试

1. 两个其他模组电池 A（满）与 B（空）接在同一个 SI 电网上，没有发电机与负载。**预期**：A 不给 B 充电，SI 储电箱也不从 A 充电。
2. 加一台 SI 机器（负载）。**预期**：A 为机器供电，降到 10% 或以下后停止（角色每 tick 决定一次，速率大的电池在最后一个 tick 可能低于 10%，见第 7 节）；之后 A 不再供电，也不从电网充电，除非电网有余量。
3. 加一台发电机并移除负载。**预期**：B 与 SI 储电箱接收余量；A 在 90% 以上时不接收。

## 4. 并网接口（(g)，Q5）

### 改动（`mio_icif_energy_converter_entity.java`、`mio_icif_block_energy_converter.java`、`mio_icif_capacities.java`、配方、语言与指南）

- 能量转换器（ID `mio_icif:energy_converter/energy_converter` 不变）改为**并网接口**：重新可以合成（配方与 0.1.10.38 相同），并列入创造模式物品栏。0.1.10.39 起它是隐藏的旧版方块。
- **正面**（放置时朝向）连接另一个电网，其余五个面接入 SI 电网。缓存 200,000 EU（原来的 100,000 EU + 400,000 FE），4 FE = 1 EU，无损耗。
- **模式**（潜行 + 右键循环）：输出（SI → 正面）→ 输入（正面 → SI）→ 双向 10% → 双向 25% → 双向 50% → 输出。
- **上限**（右键循环）：32 → 128 → 512 → 2,048 EU/t，两侧相同。默认：输出、2,048 EU/t。
- **输出**：在 SI 一侧是蓄电类接收端，每 tick 最多接收上限；每 tick 把缓存交给正面的方块（最多上限 × 4 FE）。
- **输入**：每 tick 从正面的方块取得 FE（最多上限 × 4）存入缓存；在 SI 一侧是电压包等于上限的发电机。
- **双向**：在 SI 一侧只接收发电机的余量（不从蓄电接收），只为负载供电（不为蓄电充电）。缓存高于上沿（半满 + 死区的一半）时把多出的部分交给正面，低于下沿时从正面取入所缺的部分；在死区内正面不动作。
- 其他模组只在正面看到 FE 能力：输入与双向模式下可以推入（双向：到下沿为止），输出与双向模式下可以取出（双向：高于上沿的部分）。
- **旧存档**：0.1.11.0 及更早的能量转换器加载后，FE→EU 模式变为输入模式，EU→FE 模式变为输出模式；原来的 FE 缓存以整 EU 并入 EU 缓存（不超过容量）。

### 测试

1. 在创造模式物品栏或配方查看器中找到“并网接口”，并能合成。
2. **输出**：发电机 → 线缆 → 并网接口，正面贴一个空的其他模组 FE 电池。右键把上限调到 128。**预期**：电池每 tick 收到 512 FE；`/mio_icif perf` 的“并网接口”约为 512。
3. **输入**：潜行右键一次（输入），右键把上限调到 32；正面贴一个满的 FE 电池，背面线缆通向储电箱。**预期**：储电箱与接口缓存合计每 tick 增加约 32 EU，电池每 tick 减少约 128 FE。
4. **双向**：再潜行右键一次（双向 10%）。正面贴 FE 电池，背面电网有发电机与负载。**预期**：缓存在 90,000–110,000 EU 之间时正面不动作；高于 110,000 时向正面输出，低于 90,000 时从正面取入。SI 一侧不从 SI 储电箱取电，也不为 SI 储电箱充电。
5. **旧存档**：在 0.1.11.0 中放置一个 FE→EU 模式且有 FE 缓存的能量转换器，升级后加载。**预期**：显示为输入模式，缓存为原 EU + FE ÷ 4。
6. 正面接其他模组的线缆（例如 Mekanism 通用线缆）。**预期**：输入模式下线缆可推入，输出模式下线缆可取出。

## 5. Mekanism 焦耳（(h)）

### 改动（`MekanismStrictEnergyBridge.java`、新增 `JouleSavings.java`、`FeMachineBridge.java`）

- SI 机器的焦耳视图在两次传输之间保留不足 1 EU 的焦耳。0.1.11.0 不足 1 EU 的输入被拒绝，每次输入中不足 1 EU 的部分被退回，小而持续的能量流永远到不了。
- 提取先从积存中支付，其余以整 EU 从储能取出。
- 换算率改变时积存被丢弃（不足 1 EU）。积存不保存：机器卸载时损失不到 1 EU。

### 测试（需要 Mekanism）

1. Mekanism 线缆以很小的功率（每 tick 少于 10 J，即少于 1 EU）给 SI 机器供电。**预期**：机器的电量缓慢增加（0.1.11.0：不增加）。
2. Mekanism 线缆从 SI 储电箱取电。**预期**：取出的焦耳 ÷ 10 等于储电箱减少的 EU。

## 7. 与提案的差异

1. 窗口中的端口顺序（提案未涉及）：原生结算按窗口（最多 32 个电源、128 个接收端，按端口顺序）进行公平轮次。外部端口最初接在全部 SI 端口之后，形成只有外部接收端的窗口，在其他窗口的负载还有空间时拿走电源的全部额度。现在把外部端口均匀插在 SI 端口之间（`IndependentSiEnergy.interleave`；只有 SI 端口时顺序不变）。与“接在之后”交替比较两次（精确入账）：fe_export_1k 负载 1,253.1 → 1,920.0 EU/t，FE 输出 2,667.5 → 0 FE/t；fe_export_surplus_1k 负载 2,560.8 → 7,680.0 EU/t，输出 20,476.7 → 0；fe_mixed_1k 负载 1,722.3 → 1,920.0 EU/t，输出 2,667.9 → 0、输入 1,877.0 → 0，两个方向同时有 FE 的 tick 16 → 0；fe_export_saturated_1k 输出不变（7,680 FE/t），结算 0.73 / 0.71 → 0.62 / 0.62 ms。新 GameTest `loadsComeFirstInEveryWindow` 固定这一点（在基准树中把外部端口接在 SI 端口之后时该测试失败：电池在 60 tick 中得到 3,840 FE，负载只得到 960 EU）。
2. 拒收的 FE：提案 (d) 在同一 tick 内把差额退回电源；实现中差额留在暂存单元，下一 tick 再交（端口的空间扣除这部分）。tick 之间单元中不到 1 FE；方块消失时单元中的能量计入 `ForeignTotals.dropped`。
3. 负载的额定输入不是硬上限：公平轮次在额定阶段之后还有“空间”阶段，满的外部电池（蓄电顺位）把负载补到其空间（GameTest：每个供电 tick 1,024 EU），与 SI 储电箱相同。
4. 死区每 tick 选择一次角色：角色在每帧开始时按充电率决定，一个 tick 内的数量只受方块自身速率的限制，速率大的电池可以在一个 tick 内越过整个死区。fe_mixed_1k 的 120 个电池（各 50,000 / 100,000 FE，速率 100,000 FE/t）在 47 tick 内全部放空（共 6,000,000 FE），没有停在 10%；GameTest 中一个负载每 tick 取 4,096 FE 时，电池停在 10,000 FE 以下。充电同样可以在越过 90% 的那个 tick 中超过 90%。往返仍为 0。
5. 并网接口：上限只有 EU/t（没有 FE/t 的选项；4 FE = 1 EU）；双向模式的死区按接口缓存的充电率（半满 ± 死区的一半），不是提案中“岛的余量占上限的百分比”；上限在公平轮次中以空间裁剪实现（`IndependentSiEnergy` 一处），不是分配器中的额定值；正面不能接收时，双向模式的缓存可以充到上沿以上直至满（之后 SI 一侧不再接收）。
6. 焦耳积存按机器（`FeMachineBridge.joules()`）而不是按接触；不保存，卸载时损失不到 1 EU，不计入耗散（换算率改变时丢弃的部分由 `JouleSavings.dropped()` 计数）。GameTest 用 200 次 3 J 的输入与 100 次 7 J 的提取验证；提案中 10,000 tick 的试验没有做。
7. (e) 的后果：只推送 FE 的外部发电机贴在 SI 线缆上不再供电，需要经 SI 机器或输入模式的并网接口接入。
