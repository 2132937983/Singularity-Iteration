# 0.1.8.2 更新说明

基于 0.1.8.1（工作树 `pr-0.1.8.1-20261012`）。构建环境为 Gradle 8.10.2、JDK 21、NeoForge 21.1.218，离线构建。

## 1. 作物架与交配架的严重问题

| 问题 | 原因 | 修复 |
|---|---|---|
| 右键收获时物品消失 | ① IC2 的高斯掉落次数可为 0（高等级、低产量作物约 30～40%），植物仍回到收获后阶段；② 掉落物生成在作物架方块内部，常被挤出或被方块吞掉 | 掉落次数至少为 1；没有产出时不执行收获（植物保持阶段）；玩家右键收获时掉落物直接放入物品栏（`ItemHandlerHelper.giveItemToPlayer`），放不下的掉在玩家脚下；无玩家时在作物架上方生成并带向上速度。新增 API 默认方法 `IPlanter#doManualHarvest(Player)` |
| 破坏交配架（下层）时掉落错误物品 | 返还的是方块物品而不是放上去的那根作物架 | 交配时记录所用的作物架物品（`CrossStick`），破坏或右键拆除时原样返还；旧存档没有记录时返还方块物品 |
| 纹理缺失、异常高属性、一次掉落 64 个 | 13 种配置作物没有纹理；钛／铀叶子使用旧的逐 tick 模型，产量被计算两次（最多 96 个），生长点每 tick 增加 | 新增 13 种作物的纹理与通用备用纹理（缺失纹理时不再显示紫黑方块）；钛／铀改为与其他金属作物相同的 IC2 作物周期（`OreRootCrop`：4 阶段，最后阶段需根部有矿石或储存方块，每次 1 个小撮粉，掉落概率减半）；旧存档的进度在加载时重置一次（`CropCycleVersion` 2） |
| 收获后交配状态残留 | 种植植物时没有清除杂交标志；交配架与升级作物架外观相同 | `setPlant` 清除杂交标志与记录的作物架；存档中“同时有植物和杂交标志”的作物在加载时修复；交配架新增独立模型 `stick_cross`／`stick_upgraded_cross` |

## 2. 高属性种子（10/10/10）停止生长与作物监护机

* 原因：IC2 规则下需求品质 = 4×(等级−1) + 生长 + 产量 + 抗性。10/10/10 的需求为 30 以上，环境较差时惩罚使生长点为 0，甚至触发死亡判定。作物监护机原先只补充水、营养与除草剂。
* 修复：作物监护机照料到的作物在一段时间内（`TEND_TICKS`，覆盖一轮扫描）获得“照料”状态：环境品质至少为需求 + 50（`CropGrowthMath.tendedQuality`），因此无惩罚、无死亡判定，生长至少 +50%。新增 API 默认方法 `IPlanter#markTended`／`isTended`。

## 3. 次世代作物扫描仪（原作物分析仪）

物品 ID 不变（`normal/item_crop_analyzer`），旧物品与旧内容（三槽）自动迁移。

* **性能**：容量 100,000 → 4,000,000 EU，等级 4，充电 2,048 EU/t（电池槽同速）。完整分析每袋 500 EU（旧版 10,000 EU），整堆一次分析。
* **手持 HUD**：任一只手持有有电的扫描仪并瞄准作物架时显示：植物名、学名（`CropTaxonomy`）、阶段与成熟度条、生长／产量／抗性、湿度／土壤营养／空气质量／光照、储水／营养／除草剂、环境品质与需求（生长速度或惩罚、致命风险）、照料状态，以及第一个未满足的生长条件（光照不足／过强、根部方块、储水、营养等）。数据每秒两次由服务器提供，每次读数 8 EU；没电时只显示“无电”。
* **箱子式界面**：27 个分析槽，每个槽独立显示从上向下移动的扫描线，到达底部时完成（扫描等级 4）；已分析的堆显示绿色角标。
* **超频升级槽**（4 槽，最多计入 8 张）：每张时间 ×0.7、功率 ×1.6（IC2 规则，单次任务能量 ×1.12）。最后一个 tick 只扣剩余能量，短任务不会多付整 tick。
* **交配研究**（安装：强化铱板 ×10 + 生体电路 ×1，永久）：两个已分析的亲本 → 从自然杂交候选中选择目标 → 确定得到目标种子（属性为亲本平均值，扫描等级 4），每次消耗每个亲本 1 袋，可连续运行。成本 `40,000 × 等级^1.6 × (1 + 3 × (1 − 自然概率))` EU，1,024 EU/t。
* **基因编辑**（安装：量子核心 ×1 + 中子板 ×4 + 超级电路 ×2，永久；每次另需 UU 物质，每提升 3 点 1 个）：用滑条或 −/+（Shift 为 5 点）设定生长／产量／抗性目标。提升到 v 每点 `1,000 × 1.25^v` EU（指数增长），降低每点 2,000 EU，2,048 EU/t。例：10/10/10 → 31/31/31 约 1,500 万 EU、366 秒、UU 物质 21 个。
* 任务在菜单打开期间运行；内容与进度保存在扫描仪物品中。打开期间所持扫描仪的物品栏槽位被锁定（防止复制）。
* 新增 API 默认方法 `ICropSeedItem#setCropTraits`；聊天栏诊断增加属性与环境一行。

## 4. 作物纹理全面更新

`tools/art/crops_182.py` 程序生成全部作物架阶段纹理（16×16，现代原版风格：无黑色描边、每种材质 3～4 个色阶、左上光照、各阶段布局一致）：233 张阶段纹理（11 种原型：谷物、根茎、花、灌木、芦苇、蘑菇、疣、金属作物、瓜类、树苗、特殊），以及作物架、升级作物架、交配架、升级交配架共 4 张。原先缺纹理的 13 种配置作物与 4 张备用纹理包含在内。预览图见 `previews/`。

## 5. 外部工业模组兼容

| 模组 | 方式 | 说明 |
|---|---|---|
| Immersive Engineering（园艺玻璃罩） | 188 个配方（47 种植物 × 4 个产量档） | 输入为新的配方材料 `mio_icif:crop_seed`（植物 + 产量范围）。玻璃罩用 `Ingredient#test` 检查材料且不消耗种子，种子袋及其属性不会丢失。产量 0–7／8–15／16–23／24–31 对应产物 ×1／×1.5／×2／×3。金属作物需要对应矿石或储存方块作为土壤。格式对照 IE 1.21.1 生成的配方（`cloche/wheat.json`、`red_mushroom.json`） |
| Thermal 系列（光合作用仪） | 种子袋作为催化剂 + 9 个普通物品配方 | 用 javap 确认 Thermal 按物品查找机器配方（`SingleItemRecipeManager`／`ComparableItemStack`：先按完整组件精确匹配，再按物品），无法按植物区分种子袋。因此种子袋作为光合作用仪的催化剂（使用概率 0，永不消耗；主产物 ×1.5、副产物 ×1.25、能耗 ×1.1）。另外 6 种金属富集种子、咖啡豆、大地疣、牛奶疣可直接放入光合作用仪 |
| Ender IO（农场站） | 代码集成（反射，无编译依赖） | 农场站可把种子槽中的种子袋（或基础种子）种到耕地上的空作物架上（与玩家相同规则，保留属性），并按正常作物规则收获，产物放入输出槽。作物架需手动放置。按 Ender IO 8.2.11 的 API（`com.enderio.enderio.api.farm`） |

* 新增物品标签 `mio_icif:crop_seed_bags`。种子袋**不**加入 `c:seeds`：参考整合包中机械动力：创想附加、森罗物语：厨房、星辉魔法的配方会消耗 `#c:seeds`（种子油、磨盘、祭坛），会毁掉已分析的种子袋。
* 所有配方都带 `neoforge:mod_loaded` 条件，未安装对应模组时不加载。
