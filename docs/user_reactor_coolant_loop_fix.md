# 用户 896 HU/t 热核冷却液回流修复

日期：2026-09-29。用户确认九台液体热交换机按 4＋4＋1 向三台蒸汽发生器供热；第四行的 `AJ` 按两个格子处理。

## 复现配置与热预算

```text
C Y A A J A J A A
Y S Y J C J C J A
A Y J C J C J C J
A J C J C J C J A
J C J C J C J C J
A J A J A J A J A
```

C 为超频散热片，S 为四联铀棒，Y 为铱中子反射板，J 为元件散热片，A 为空。

当前已对齐的核心模型：每 20 tick 产热 448，第一轮排热 336，随后排热稳定为 448，堆温为 16。热核将排热乘 40，因此稳态为 `448×40÷20 = 896 HU/t`，冷却液转换量为每周期 896 mB，即平均 44.8 mB/t。

九台满配热交换机总上限 900 HU/t，即平均每 tick 最多冷却 45 mB。额定容量足够，但仅有 4 HU/t 的余量，长期少抽热会导致热液积压。

## 确认的根因

`MioIcifCapabilitiesImpl.HeatCapabilityAdapter` 的静态初始化通过反射在 `core.api.heat.IHeatStorage` 上查找 `getMaxReceive` / `getMaxExtract`。该接口没有这两个方法，异常被吞掉后适配器始终返回 null。

液体热交换机的能力注册依赖这条适配路径，所以蒸汽发生器查询不到热源，无法主动取热。液体热交换机剩下 `carriedHeat > 0` 才执行的兜底推送：一 tick 补满热缓冲，下一 tick 才推走。结果约为半速冷却。

实测修复前：仅装入 2000 mB 冷却液，约第 100 tick，堆芯冷罐只剩 45 mB，九台换热机热罐合计 1955 mB，堆温升至 243。总液体没有丢失，热液已送到换热机，但不能及时冷却。四机供热的锅炉每 20 tick 只升温约 1.9℃，符合隔 tick 收热并在空闲 tick 冷却的表现。日志：`build/user-reactor-loop/diagnostic.log`。

## 修改

1. 将热能力桥接改为编译期类型检查和直接委托。已有平台热能力保持原对象；基础热接口也可适配，不再因缺失可选速率方法而整条失效。
2. 液体热交换机公开真实、实时的正面热能力，取消独立复制的热缓冲快照。缓存能力可以观察后续补热，模拟抽取不扣热，多次查询不能重复提取同一份 HU；拆除传导器后更新输出上限。
3. 蒸汽发生器每轮一次性扣除收到的 HU，在局部余额中分配升温、汽化与剩余热。避免剩余热先在 `work()` 内升温、随后又被 tick 尾部读到并重复升温。221 bar 的汽化成本保留 IC2 的浮点数值，不再对每批向上取整。

未提高流体弹出升级速度、热交换机额定功率或冷却液容量。现有存档字段、方块和物品 ID 保持不变。

## 真实机器验证

`UserReactorLoopGameTests` 搭建真实堆芯、六个反应室、完整外壳、九个流体端口、九台各装十个传导器的液体热交换机、三台 221 bar 蒸汽发生器。端口和换热机各装一个任意方向流体弹出升级；锅炉流量为 1000、1000、1。

只在启动时加 2000 mB 冷却液，此后不补充、不手动转移冷却液、不直接抽 HU。每 tick 核验液体总量和堆温，连续 10000 tick，约相当于正常 20 TPS 下 8 分 20 秒。

修复后采样：

- 冷却液总量始终为 2000 mB；堆温稳定为 16。
- 同一周期相位的稳定采样：堆芯冷罐 1149 mB、热罐 446 mB，九台换热机热罐各 45 mB。数值随周期相位变化，但没有持续积压。
- 三台锅炉都完成预热并稳定产汽。第三台只分到约 96 HU/t，冷启动所需时间明显长于前两台；预热期间仍正常冷却热液，不能把尚未产汽当成停止换热。
- 冷却回路测试以持续蒸馏水供应及持续蒸汽接收作为外部边界；本次没有把蒸汽动能发生机、冷凝机、动能发电机全部装进场景。因此不据此宣称下游水回收、电力输出及所有实机朝向都已验证。

另由 `HeatPortGameTests` 检查热能力适配、缓存能力的实时性与传导器拆除、锅炉剩余 HU 只记账一次。

最终结果：**27/27 GameTest 通过，32/32 核电数值检查通过，完整 Gradle build 通过**，包含 core 架构及分发检查。日志：`build/user-reactor-loop/final-gametest.log`、`build/user-reactor-loop/build.log`。产物：`build/libs/mio_icif-0.1.7.14.jar`（本轮重新构建，版本字符串未变）。

## 使用

安装本轮重新构建的完整模组 JAR 并重启游戏/服务器后，按原来的九机布局运行。各热交换机的热输出正面需要朝向对应锅炉；锅炉持续供水并保持蒸汽去路通畅。增加冷却液只增加缓冲，不能代替修复半速换热。

测试里的 2 桶是此复现场景验证过的初始量，不是任意管道、存储罐与机器布局的通用最小量。
