# 原子炉事故調査

<Row>
  <ItemImage id="mio_icif:reactor/item_reactor_blackbox" scale="3" />
</Row>

## 機能

すべての[原子炉発電機](generator_block_nuclear_reactor_generator.md)はフライトレコーダーを持つ。
原子炉サイクル（1 秒）ごとに 1 件の記録を書き、最新 40 サイクルを保持する。
原子炉が事故を起こすと、サーバーは記録を事故として保存し、原因を分析する。
調査レポートには、何がどこで、なぜ起きたかが表示される。

サーバーは最新 64 件の事故を保持する。記録はワールドと一緒に保存される。

## 事故として記録されるもの

| 出来事 | 種類 | ブラックボックス |
|---|---|---|
| 核爆発 | 核爆発 | 現場に落ちる |
| 原子炉の局所爆発 | 原子炉爆発 | 現場に落ちる |
| コンフィグで原子炉の爆発が無効のまま炉熱が上限に達した | メルトダウン（爆発無効） | なし（原子炉は残る） |
| 稼働中、または炉熱 10 % 以上の原子炉を撤去した | 高温状態で撤去 | なし |

ブラックボックスは燃えず、爆発にも耐え、発光し、消滅しない。

## レポートを開く

* 原子炉ブラックボックスを使う（右クリック）。持っている人なら誰でもレポートを読める。
* `/mio_icif reactor audit` で事故を新しい順に一覧表示する。行をクリックするとレポートが開く。
* `/mio_icif reactor audit 12` で事故 12 のレポートを開く。
* `/mio_icif reactor audit clear` で記録を消去する（オペレーターのみ）。

プレイヤーが見られるのは、自分の原子炉の事故と、自分が近く（64 ブロック以内）にいた事故。
オペレーターはすべての事故を見られる。原子炉の所有者は、それを設置したプレイヤー。

## レポートの内容

* **ヘッダー**: 事故番号、種類、日時、ゲーム内の日数、ディメンション、座標、所有者、近くにいたプレイヤー。
* **主因**は赤で、説明と対策つきで表示される。その下に副次的要因が並ぶ。
* **炉心レイアウト**: 最終サイクルのスロット。
  * 融解した部品は元のスロットに赤い × 付きで表示される。寿命切れの反射板はオレンジ。
  * 枯渇燃料は灰色。スロット下のバーは部品の熱、または燃料棒の残り燃料を示す。
  * 暗い列にはチャンバーがなかった。
  * スロットにカーソルを合わせると詳細が出る。
* **グラフ**: 最近 40 秒の炉熱。赤い破線が上限。
  オレンジの棒は 1 サイクルの発熱、青い棒は除熱。グラフにカーソルを合わせると各サイクルの値が出る。
* **メトリクス**（最終サイクル）: 炉熱、発熱と除熱、EU/t、供給倍率、列数、冷却液、燃料棒、冷却部品、自動化。

## 原因

| 原因 | 意味 |
|---|---|
| 熱暴走：冷却不足 | 炉熱が数サイクル上がり続けた。炉心の発熱が部品の除熱を上回っていた。 |
| 冷却部品の融解による熱暴走 | ベント・セル・熱交換器が融解し、その熱が炉に入った。 |
| 内部高温冷却液タンク満杯による排熱停止 | 流体炉: 高温冷却液が送り出されなかった。 |
| 冷却液切れ | 流体炉: 低温冷却液が尽きた。 |
| 液体冷却の停止 | 発電機モード: 液体冷却の冷却液が尽きたか、高温冷却液が抜き取られなかった。 |
| 外部からの許容電圧超過（機械の爆発） | 事故の直前に、原子炉の隣の機械が過電圧で爆発した。 |
| 原子炉チャンバーの喪失 | チャンバーが撤去または破壊され、その列の部品が落ちた。 |
| 未読み込みチャンク内の原子炉チャンバー | チャンバーのあるチャンクが読み込まれていなかった。原子炉は 1 つのチャンクに収めること。 |
| 急激な熱上昇 | 炉熱が 1 秒で半分未満から上限に達した。 |
| 稼働中の燃料追加、高い供給倍率、自動化によるアイテムの出し入れ、冷却部品の飽和 | 副次的要因。 |

## 注意

> **ヒント:** 設計はまず[原子炉シミュレーター](reactor_simulator.md)で試すこと。同じ計算を使っている。

レコーダーはメモリ上にしかない。ワールドの読み込み直後はまだサイクルの記録がない。
